# Приёмка рута

Приёмку делает архитектор недели. Агент готовит проверку и черновик вывода, решение принимает человек.

## 1. Подготовка

1. `git pull --rebase`, если есть remote. Убедись, что `git config user.name` совпадает с полем «архитектор недели» в `team.md`. Если нет — сделай только отчёт для человека, в файл не пиши.
2. **Самоприёмка** — владелец рута и есть архитектор недели. В команде принимает техлид потока или предыдущий архитектор по истории в `team.md` — скажи, кто, и остановись. В соло — допустимо, первая строка «Приёмки рута» начинается с «самоприёмка».
3. Статус рута — «Приёмка». Если нет — скажи, на каком он этапе, и остановись.
4. `python3 tools/kb.py context PM-XX` — файл шага, место на карте, журнал по руту, нарезка других рутов. Плюс `core/domain-model.md` и `core/context-map.md`.

## 2. Что проверить

### Полнота
- Все разделы шаблона заполнены или явно помечены, почему пусто.
- Выполнен список готовности к сверке из `kb-explore` §7; файл сверки `materials/interviews/*-sverka-PM-XX.md` есть, его ответы перенесены в шаг.
- Объёмы и время — числами. Боль — числами.
- Есть исключения с реальными примерами. Случаи в `datasets/PM-XX/` обязательны, только если в пуле есть тестировщик (`team.md`).

### Качество фактов
- У каждого факта есть источник и статус. Выбери 3–5 фактов и открой источник: действительно ли там так написано.
- Нет фактов «из опыта».
- Противоречия либо разрешены, либо по ним есть вопрос нужного типа (таблица «Тип вопроса» в `AGENTS.md`).

### Нарезка
- Каждый декомпозит убирает боль из раздела «Боль».
- Размер 1–3. Больше — вернуть на нарезку.
- Зависимости записаны явно, циклов нет.
- Ничего общего для нескольких рутов не нарезано внутри рута — оно в `PM-00`.
- Нет пересечений с декомпозитами других рутов.

### Журнал
- У каждого открытого допущения есть «Если ошиблись» и дата проверки.
- Риски с высоким влиянием по руту заведены, у них есть план Б.
- Необратимые вопросы (ключи, миграции, деньги, внешние контракты, персональные данные) закрыты решениями, а не допущениями.
- Блокирующие вопросы: по каждому декомпозиту — есть ли открытый вопрос с ним в `блокирует` без допущения.

## 3. Результат

| Результат | Когда | Статус рута |
|---|---|---|
| Принят | Всё выполнено | «Декомпозиты в работе» |
| Принят с условиями | Можно начинать хотя бы один декомпозит, но с ограничениями: порядок, зависимость от PM-00, не выключать старый процесс, пока открыто допущение | «Декомпозиты в работе», если хотя бы у одного декомпозита нет открытых блокирующих вопросов без допущения; иначе остаётся «Приёмка» с условиями |
| Возвращён | Нет фактов по ключевым разделам, нарезка не от боли, общее спрятано в рут, необратимое на допущении | Назад: «Нарезка» или «Разбор» |

## 4. Записать

Это названное исключение из правила «один файл — один писатель»: архитектор пишет в файл шага только раздел «Приёмка рута» и статус.

1. `python3 tools/kb.py append PM-XX "Приёмка рута" "Архитектор недели: <имя>, <дата>, результат: <…>"`, затем каждое условие: `… append PM-XX "Приёмка рута" "- <условие с ID>"`.
2. Статус: принят — `python3 tools/kb.py set PM-XX статус="Декомпозиты в работе"`; возвращён — `python3 tools/kb.py set PM-XX статус=<Нарезка|Разбор> --force "<причина>"` (причина сама запишется в «Приёмка рута»). Остаётся «Приёмка» с условиями — статус не трогай.
3. Нашёл проблему, которая касается других рутов или ядра — вопрос через `kb-ask` или решение через `kb-decide`.
4. `python3 tools/kb.py check`. Отправка — по таблице «Режим работы» в `AGENTS.md`: `git commit -m "PM-04: приёмка рута — принят с условиями (D-001, A-001)" -m "Скилл: kb-accept" -- <файл шага>`. Ревьюер MR — владелец рута.

## 5. Скажи человеку

Результат, условия по пунктам, какие декомпозиты можно брать первыми, что вызвало сомнения. Владельцу — одна строка в чат.
