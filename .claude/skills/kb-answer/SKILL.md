# Записать ответ

Ответ существует, только когда он записан в базу знаний коммитом. Закрыть вопрос без записи ответа нельзя.

## 1. Подготовка

1. `git pull --rebase`, если есть remote.
2. Найди вопрос или допущение по ID. Если человек принёс ответ без ID — найди по смыслу в `journal/_index.md` и уточни у него.
3. Проверь, кто ответил и как: письменно с именем и датой, ссылкой на регламент, кодом или проверкой на данных. Устное «вроде да» без имени — не ответ. Молчание — не ответ.
4. Чем можно закрыть — по типу вопроса (таблица «Тип вопроса» в `AGENTS.md`): кодом или данными — только «понимание» и «факт о системе»; «бизнес-правило» — только ответом бизнеса. Код расходится с регламентом — это противоречие (правило 3 `AGENTS.md`), а не ответ.
5. Письменный ответ бизнеса (письмо, сообщение) сохрани в `materials/answers/<дата>-<роль>.md`: роль, дата, «Обезличено: да», текст.

## 2. Записать факт

Ответ уже в вопросе с пометкой «Записан в: ждёт владельца» (его записал аналитик после созвона), а ты владелец шага — перенеси факт по пунктам ниже; источник — файл созвона из ответа. Затем точечной правкой замени «ждёт владельца» на «<файл#раздел>». Статус вопроса уже `отвечен`. Ответы по `ROOT` и рутам без владельца переносит аналитик (`whoami` — «Ответы без хозяина»).

1. Определи, в какой файл и раздел ляжет ответ: шаг `PM-XX`, система `SYS-XX`, `core/`, глоссарий, `product.md`.
2. Запиши факт: `python3 tools/kb.py fact PM-XX "<Раздел>" "<текст>" "<materials/answers/… или materials/interviews/…, Q-…>" подтверждено`.
3. Если файл принадлежит другому владельцу — не правь его напрямую: маленький MR с одной правкой, ревьюер — владелец.
4. Если ответ противоречит уже записанному факту — не перезаписывай молча: оба варианта с источниками, статус `противоречие`, вопрос через `kb-ask`.

## 3. Закрыть вопрос

1. `python3 tools/kb.py append Q-… Ответ "<кто>, <дата>, <источник>: <суть>. Записан в: <файл#раздел>"`. «Ответ» дописывает любой, кто принёс ответ с источником.
2. Статус `отвечен` — кто может, по правилу 4 `AGENTS.md`. Не можешь — допиши строку в «Уточнения» и сообщи автору.
3. **Частичный ответ:** суть отвечена — `отвечен`, остаток новым узким вопросом (`kb-ask`); суть не отвечена — услышанное в «Уточнения», статус не меняй.
4. Подписчикам — короткое сообщение в чат пула со ссылкой на файл.

## 4. Если ответ касается допущения

Сначала найди все места: `python3 tools/kb.py refs A-…`.

**Подтверждено:**
1. `python3 tools/kb.py set A-… статус=подтверждено` и `python3 tools/kb.py append A-… "Чем закрыто" "<кто>, <дата>, <как>"`.
2. В своих файлах: статус факта `допущение A-…` → `подтверждено (A-…)`.
3. Владельцам остальных мест из списка `refs` — сообщение: допущение подтверждено, пометки можно снять. Участок процесса теперь можно переводить на систему полностью.

**Опровергнуто:**
1. В допущении: статус `опровергнуто`, «Чем закрыто» — что на самом деле.
2. Запиши правильный факт по шагу 2.
3. По каждому месту из `refs` составь список для человека: файл, что там сейчас, что поменять. Сгруппируй по декомпозитам.
4. Для декомпозитов в работе и в проде — **не меняй код и спеки сам.** Скажи человеку, что владельцам нужно завести изменение спеки, и если декомпозит на бою под тоглом — решить, выключать ли тогл.
5. Рут уже в нарезке или дальше, а факт ключевой — владелец возвращает статус: `python3 tools/kb.py set PM-XX статус=Разбор --force "опровергнуто A-…"`.

## 5. Проверка и отправка

Отправка — по таблице «Режим работы» в `AGENTS.md`: факт в шаге — MR, строки в журнале — прямой коммит.

1. `python3 tools/kb.py check`.
2. Коммит с ID: `git commit -m "PM-04: источник правды по долгу — 1С МФО (Q-014, A-007 подтверждено)" -m "Скилл: kb-answer" -- <файлы>`.

## 6. Скажи человеку

Что записано и где, какие объекты закрыты, кого нужно уведомить и, если допущение опровергнуто, какие декомпозиты затронуты.
