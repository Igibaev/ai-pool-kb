# Золотой датасет рута

Датасет — это набор случаев «вход → ожидаемый результат» на реальных обезличенных данных. Из него берут цифры для сценариев спек и эталон для проверки кода (`kb/docs/proverka-koda.md`). Ожидаемый результат — **только из источника**: правило шага, ответ бизнеса, документ. Нет источника — нет ожидания, есть вопрос.

## 1. Когда и что делать

| Когда | Что делаем |
|---|---|
| Рут в «Разборе» | Матрица покрытия по фактам шага; случаи с данными из материалов; пробелы — вопросами |
| После сверки с бизнесом | Ожидания из ответов бизнеса: «допущение» и «ждёт Q-…» → «подтверждено» |
| Нарезка (`kb-slice`) | У каждого случая — декомпозит, который его проверяет; у каждого декомпозита — хотя бы один случай |
| На бою нашли случай, которого нет | Новый случай с пометкой «с боя», ссылка на инцидент |

## 2. Подготовка

1. `python3 kb/tools/kb.py whoami`. `kb/datasets/PM-XX/` пишет тестировщик — владелец или напарник рута. Иначе — предложи случаи владельцу рута вопросом (`kb-ask`), файлы не создавай.
2. `python3 kb/tools/kb.py context PM-XX` — правила, исключения, объёмы, идентификаторы, открытые вопросы и допущения по руту.
3. Что уже есть: `ls kb/datasets/PM-XX/` и `kb/datasets/PM-XX/README.md` (матрица покрытия). Номер следующего случая — следующий за последним `GD-PM-XX-NNN`.

## 3. Матрица покрытия — сначала список, потом данные

Пройди по фактам шага и выпиши, какие случаи нужны. Покажи список человеку до того, как искать данные: он тестировщик, он знает, где ломается.

| Источник в шаге | Какие случаи |
|---|---|
| Каждое правило («Правила») | Обычный случай: правило срабатывает. Случай, где правило **не** срабатывает |
| Порог, лимит, срок («10 000 тг», «2 месяца», «21:00») | Три случая: ровно на пороге, на шаг ниже, на шаг выше |
| Каждое исключение («Исключения») | Случай из реальных данных, где это исключение было |
| Идентификаторы | Номер сменился; номер повторился; номера нет; номер в другом формате |
| Время («Объём и время», «Правила») | Конец дня и периода, выходной, задержка поступления данных |
| Деньги | Частичная оплата, переплата, оплата после формирования списка, копейки и округление |
| Противоречие | Случай, где два источника дают разный результат; ожидание — «ждёт Q-…» |
| Объём | Один «тяжёлый день» — пиковый объём из «Объём и время», для нагрузки |

Пример. Правило «претензия при долге больше 10 000 тг» даёт случаи: долг 10 000, 9 999, 10 001; долг больше порога, но абонент заплатил после выгрузки 1-го числа.

Спроси человека одним сообщением: «Каких случаев не хватает? Где на бою чаще всего ошибаются? Какие случаи помните сами?» Случай «из памяти» без данных — не случай: вопрос бизнесу «покажите такой пример».

## 4. Данные для случая

1. Ищи реальную строку в материалах: `python3 kb/tools/kb.py peek <файл>`, затем отбор скриптом (pandas или csv) по условию случая. Цитируй файл и номер строки.
2. **Обезличь до записи:** ФИО → «Абонент 17», телефон → `+7 701 ***-**-**`, ИИН → `3140590*******`, адрес → «ул. Улица 1, кв. 5». Формат и длина сохраняются, чтобы правила остались видны.
3. Реальной строки нет — можно собрать синтетическую по правилу: `данные: синтетические`, в «Откуда известно» — какое правило воспроизводим. Ожидание всё равно — из источника.
4. Ожидаемый результат — из правила шага (`PM-XX «Правила», строка`), ответа бизнеса (`Q-…`), документа. Ожидание взято из старого скрипта, а скрипт мог ошибаться, — «допущение».

## 5. Записать случай

Файл `kb/datasets/PM-XX/GD-PM-XX-NNN-<slug>.md` по шаблону из `kb/datasets/README.md`. Одно поле — одно значение. `статус ожидания`:
- `подтверждено` — источник проверяемый или бизнес ответил;
- `допущение A-…` — только оформленное через `kb-assume`;
- `ждёт Q-…` — ответа нет. Нет вопроса — заведи: `python3 kb/tools/kb.py new question <slug> тип=бизнес-правило раздел=PM-XX заголовок="Какой результат ожидается, когда …?"`.

Обнови матрицу покрытия в `kb/datasets/PM-XX/README.md`: строка на правило или исключение → ID случаев → пробел.

## 6. Проверка и отправка

1. `python3 kb/tools/kb.py check` — ошибок 0. Персональные данные в `kb/datasets/` — ошибка, а не предупреждение.
2. Коммит, затем `python3 kb/tools/kb.py push` (раздел «Git» в `AGENTS.md`): `git commit -m "PM-04: датасет, 6 случаев (GD-PM-04-001…006)" -m "Скилл: kb-dataset" -- <файлы>`.
3. `python3 kb/tools/kb.py note "датасет PM-XX: N случаев; дальше: …"`.

## 7. Скажи человеку

Сколько случаев и сколько из них «подтверждено», какие правила и исключения пока без случаев, какие вопросы заведены. Следующий шаг: после сверки — обновить ожидания; при нарезке — привязать случаи к декомпозитам.
