# Нарезка рута на декомпозиты

Декомпозит — это срез, который можно довести до прода отдельно: у него своя спека, свои сценарии и понятная польза.

## 1. Можно ли начинать

1. `git pull --rebase`, если есть remote.
2. Ты владелец рута: `git config user.name` совпадает с полем `владелец рута`. Если нет — нарезку делает владелец, ты можешь только предложить вариант в чате или MR.
3. Статус рута — «Сверка с бизнесом» и есть файл сверки `materials/interviews/*-sverka-PM-XX.md` (его пишет аналитик, `kb-interview` режим В). Нет файла — **стоп**, нарезать нельзя: скажи, что сверка ещё не проведена. Список готовности шага — `kb-explore` §7.
4. Вопросы, которые блокируют понимание шага, закрыты ответом или допущением; ответы из файла сверки перенесены в шаг: в `python3 tools/kb.py whoami` владельца нет строки «Ответы ждут переноса» по этому руту. Есть — сначала `/kb-answer`.
5. `python3 tools/kb.py set PM-XX статус=Нарезка`.

## 2. Что прочитать

- `core/domain-model.md` и `core/context-map.md` — какие сущности и модули уже есть.
- `python3 tools/kb.py context PM-XX` — файл шага, журнал по руту и нарезка **других** рутов, чтобы не нарезать то же самое второй раз.

## 3. Как резать

1. Отталкивайся от боли из раздела «Боль»: один декомпозит убирает одну боль или делает один переход состояния главного объекта.
2. Размер — 1–3 дня работы человека с агентом. Больше — режь дальше.
3. Вертикально: бэк, фронт и тесты внутри одного декомпозита, не отдельные декомпозиты на слои.
4. Независимо. Если зависимость неизбежна — запиши её явно в колонке «Зависит от».
5. Первым — самый больной и самый простой срез, который даёт результат на бою.
6. **Общее — не к себе.** Если декомпозиту нужна сущность, интеграция или правило, которые понадобятся и другим рутам, — это часть `PM-00 Каркас и общие части`. Не нарезай его в свой рут: создай вопрос через `kb-ask` с типом «скоуп» и разделом `PM-00`, а у себя укажи зависимость.
7. **Пересечения.** Если в другом руте уже есть похожий декомпозит — не дублируй. Укажи зависимость от него или задай вопрос его владельцу и архитектору недели.

## 4. Записать

1. Заполни таблицу «Нарезка на декомпозиты» в файле шага: ID `PM-XX-01`, `PM-XX-02`… (номера внутри своего рута выдаёшь ты, конфликтов нет), название, какую боль убирает, зависит от, размер.
2. Спеки не пиши — их пишут, когда декомпозит берут в работу.
3. `python3 tools/kb.py set PM-XX статус=Приёмка`.

## 5. Проверка и отправка

Отправка — по таблице «Режим работы» в `AGENTS.md`.

1. `python3 tools/kb.py check` — ссылки на чужие декомпозиты должны существовать.
2. Коммит: `git commit -m "PM-04: нарезка на 4 декомпозита" -m "Скилл: kb-slice" -- <файл шага>`. Ревьюер MR — архитектор недели.

## 6. Скажи человеку

Сколько декомпозитов, какие зависимости, что ушло в общие части, какие пересечения с другими рутами найдены и что архитектору недели нужно проверить в первую очередь.
