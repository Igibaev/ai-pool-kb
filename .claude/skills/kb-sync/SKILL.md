# Дежурство по базе знаний

Запускается 2 раза в день: утром — дайджест для всех, около 15:00 — пакет вопросов для бизнеса. Результат — один файл `journal/digest/ГГГГ-ММ-ДД.md` и правки статусов.

## 1. Подготовка

1. Дежурный — поле `дежурный по знаниям` в `team.md` (ротация по неделям, нести может любой из пула). Имя не совпадает — скажи, кто дежурный на этой неделе, и спроси, делать ли всё равно.
2. `git checkout <основная ветка> && git pull --rebase`, если есть remote.
3. Найди, с какого момента синхронизировать: последний файл в `journal/digest/` и коммит, указанный в нём строкой `Синхронизировано до: <хеш>`. Если дайджестов нет — последние 24 часа: `changes --since "<дата и время сутки назад>"`.
4. `python3 tools/kb.py index` (для просмотра, в коммит не идёт) и `python3 tools/kb.py check`. Ошибки проверки перенеси в дайджест — их исправляют авторы.

## 2. Ответы в новых коммитах

1. `python3 tools/kb.py changes --since <хеш>` — коммиты, новые объекты журнала и изменённые строки. Файлы целиком открывай, только если строк мало для вывода.
2. Для каждого открытого вопроса из `journal/_index.md` проверь, не отвечает ли на него одно из изменений — по смыслу. Кодом или данными закрываются только «понимание» и «факт о системе» (таблица «Тип вопроса» в `AGENTS.md`).
3. Если похоже на ответ — `python3 tools/kb.py set Q-… статус="возможно отвечен"` и `python3 tools/kb.py append Q-… Уточнения "дежурный: возможно, ответ в <файл#раздел>"`. **Сам не закрывай** — закрывает автор, подтвердив, что ответа достаточно (правило 4 `AGENTS.md`).

## 3. Дубли

1. Для каждого нового вопроса: `python3 tools/kb.py similar "<заголовок>" "<другая формулировка>"` и заголовки открытых вопросов из `journal/_index.md`. Сравнивай по смыслу.
2. Дубль: `python3 tools/kb.py set <поздний> статус=дубль`, `python3 tools/kb.py append <поздний> Ответ "Дубль <ранний>"`, `python3 tools/kb.py append <ранний> Подписчики "<автор дубля>"`, `python3 tools/kb.py append <ранний> Уточнения "<автор>: <нюанс>"`.
3. Сомневаешься — не склеивай, вынеси в дайджест как «возможные дубли».

## 4. Противоречия

Что такое противоречие — правило 3 `AGENTS.md`.
1. Пройди изменённые строки про правила, источники правды и объёмы и сравни их со всеми фактами того же шага.
2. Для каждой такой строки — `python3 tools/kb.py similar "<суть факта>"`: на ту же тему в других файлах может быть записано другое.
3. Нашёл — не выбирай сам, кто прав. Если по теме уже есть открытый вопрос — допиши ссылки в его «Уточнения». Нет — `python3 tools/kb.py new question <slug>` с двумя ссылками, тип — по правилу 3. Вынеси в дайджест.

## 5. Сроки

- Пакет для бизнеса — в дневной запуск. Туда — вопросы к бизнесу по таблице «Тип вопроса» в `AGENTS.md` («понимание», «бизнес-правило», «факт о системе»; «решение» и «скоуп» — нет), открытые больше 4 рабочих часов (рабочие часы — поле `рабочие часы` в `team.md`), статус `ждёт бизнес`. Утренний запуск статусы `ждёт бизнес` не ставит.
- Туда же — вопросы со статусом `стал допущением` и открытые допущения с полем `кто проверяет`, с пометкой «подтвердите A-…».
- Вопросы, открытые больше 2 рабочих дней и блокирующие декомпозиты, — в дайджест с рекомендацией оформить допущение.
- Допущения с прошедшей датой «проверить до» — статус `просрочено`, в дайджест для техлида потока.
- Руты в «Сверке с бизнесом» без файла `materials/interviews/*-sverka-PM-XX.md` — в дайджест для аналитика: нужен созвон (`kb-interview` режим В).
- Открытые риски с высоким влиянием — в дайджест каждый день. Если в новых коммитах или ответах бизнеса видно, что сигнал риска сработал, — допиши в «История» риска строку `дежурный: возможно, сработал сигнал — <что увидел>` и вынеси в дайджест для того, кто следит.

## 6. Дайджест

Создай `journal/digest/ГГГГ-ММ-ДД.md` (если файл за сегодня есть — допиши новый раздел со временем):

```markdown
# Дайджест ГГГГ-ММ-ДД, <время>
Синхронизировано до: <хеш HEAD>

## Что изменилось в базе знаний
- PM-04: <что добавили>, <кто>

## Закрыто
- Q-014 отвечен: <суть>, записан в <файл>

## Возможно отвечено — авторам проверить
- Q-021 (<автор>): ответ, похоже, в <файл#раздел>

## Склеены дубли / возможные дубли

## Противоречия — нужно решение

## Ждут сверки с бизнесом
- PM-04 — владелец <кто>, созвон не назначен

## Пакет для бизнеса
Письмом — короткие вопросы. Где нужен показ или разговор — созвон: `/kb-interview`.
Сгруппировано по темам, без дублей, одной фразой каждый вопрос.
### <тема>
- Q-… <вопрос> — кто ждёт: <подписчики>, блокирует: <…>
### Подтвердите
- A-… <что приняли> (Q-…) — кто проверяет: <…>

## Просрочено
- A-007 проверить до <дата>, кто проверяет: <…>

## Рекомендовано оформить допущение

## Риски с высоким влиянием
- R-003 <риск> — следит: <кто>, сигнал: <…>

## Ошибки проверки
```

## 7. Отправка

Отправка — по таблице «Режим работы» в `AGENTS.md`: прямой коммит в основную ветку, только свои файлы (дайджест и объекты журнала; сгенерированные файлы не добавлять).

1. `python3 tools/kb.py check` ещё раз.
2. `git commit -m "kb-sync: дайджест ГГГГ-ММ-ДД" -m "Скилл: kb-sync" -- journal/digest/ГГГГ-ММ-ДД.md <объекты журнала>`, push, если есть remote.

## 8. Скажи человеку

Кратко: сколько закрыто, сколько ждёт бизнес, что просрочено, есть ли противоречия. Пакет для бизнеса аналитик просматривает и отправляет сам — агент бизнесу не пишет.
