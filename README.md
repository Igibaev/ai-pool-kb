# Пул и агенты: база знаний продукта

Процесс разработки под ИИ-агентов: один пул (разработчики, тестировщики, аналитики, веб), канбан, работа от спецификаций. Путь работы: карта процессов → руты (шаги карты) → декомпозиты → спеки → код. Знания о продукте живут в git-репозитории, агенты наполняют его по скиллам, люди приносят материалы и проверяют.

Работает в Claude Code (и вкладке Code в Claude desktop) и в OpenCode со своей моделью.

## Что здесь

```
project-template/            шаблон репозитория продукта — копируется для каждого нового продукта
  AGENTS.md                  правила для агентов
  .claude/skills/            15 скиллов: kb-init, kb-map, kb-take, kb-explore, kb-ask, kb-interview, kb-activity, …
  .opencode/                 агент и команды для OpenCode
  tools/kb.py                проверка, сводки, номера, карта картинкой, взятие рутов
  docs/                      инструкции для людей — начать с docs/README.md
sim/                 симуляция «Неделя в репозитории»: сценарий, сборка, экзамен модели
game/                        игра на один день: два набора материалов и ответы бизнеса для ведущего
nedelya-v-repozitorii.html   готовая страница симуляции — открыть в браузере
```

## С чего начать

0. **Сыграть.** `game/README.md` — прогон процесса на выдуманном продукте за один день: материалы в `inbox/`, бизнес играет ведущий. Два набора: взыскание долгов за воду и сервисный центр.

1. **Посмотреть, как это выглядит в работе.** Откройте `nedelya-v-repozitorii.html`: пять дней работы пула над продуктом «мастер-система взыскания» — кто что делает, что пишет агенту, что агент спрашивает, какие коммиты получаются. Внизу — шпаргалка «Что можно написать агенту».
2. **Прочитать правила.** `project-template/docs/README.md` — порядок чтения документов.
3. **Попробовать на своём продукте.** `project-template/docs/setup.md` — установка, `project-template/docs/test-run.md` — пилот по шагам. Замечания — в `FEEDBACK.md` нового репозитория.

## Новый продукт из шаблона

```
cp -r project-template ~/work/moy-produkt
cd ~/work/moy-produkt
git init -b main
git config user.name "Имя"        # ровно как в team.md
git add -A && git commit -m "Шаблон проекта"
python3 tools/kb.py check         # Итог: ошибок 0
```

Дальше в агенте: `/kb-next`.

## Симуляция

Нужны Python 3.9+ и git.

```
cd sim
python3 build.py
```

Через 10–20 секунд появятся `sim/out/repo/` — настоящий git-репозиторий недели (коммиты, ветки, слияния, номера от CI) и `sim/out/nedelya-v-repozitorii.html`. Сборка после каждого события запускает `kb.py check` и останавливается на ошибке.

| Файл | Что в нём |
|---|---|
| `story.py` | События по порядку: правки файлов и коммиты |
| `dialogs.py` | Сессия с агентом для каждого события |
| `phrases.py` | «Можно сказать и так» к событиям и шпаргалка по скиллам |
| `exam.py` | Экзамен модели на двух шагах с автоматической оценкой |
| `player.tpl.html` | Шаблон страницы |

Экзамен своей модели (например, в OpenCode):

```
python3 exam.py prepare explore ../exam-explore
# в папке ../exam-explore запустить агента с заданием из вывода
python3 exam.py grade explore ../exam-explore
```

Подробнее — `project-template/docs/opencode.md`.

## Главные правила

1. Факт — только с источником и статусом: `текст (источник, подтверждено | оценка | допущение A-… | противоречие)`.
2. Ответ существует, только когда записан коммитом.
3. У файла один писатель: шаг — владелец рута (и напарник, если рут на двоих), карта — аналитик, ядро — архитектор недели.
4. Руты не назначают — разработчики берут сами: `kb.py ready`, `kb.py take`.
5. С бизнесом говорит аналитик: вопросы пула собираются в один созвон.
6. Процесс и инструмент настраивает руководитель: раз в неделю `/kb-activity` — кто что делал, где буксует, что поправить.
7. Персональные данные в репозиторий не попадают — материалы обезличиваются до коммита.
