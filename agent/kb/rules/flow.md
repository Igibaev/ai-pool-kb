# Флоу: 8 этапов

По этому файлу работает штурман. Вопрос «где я, что дальше» получает ответ в три строки: «ты здесь, дальше вот это, вот почему».
**РЕШАЕТ** — решение за этим человеком. Агент предлагает, но не решает.
Модель: Л — лёгкая, С — средняя, Т — тяжёлая (`models.md`).

## Статусы шага

```
Черновик → Готов к взятию → Разбор → Сверка с бизнесом → Нарезка → Приёмка → Декомпозиты в работе → Готово
```

Статусы декомпозита: `Нарезан → Спека → Сборка → Ревью → Приёмка → Готово`.
«Ждёт ответов» — признак, а не статус. Его считает инструмент: шаг в «Разборе», и у него есть открытые блокирующие вопросы.

## 1. Карта процессов

Статус шага: Черновик → Готов к взятию.

| Кто | Что делает |
|---|---|
| Бизнес | Приносит запрос, регламенты, выгрузки, схемы |
| Аналитик — **РЕШАЕТ** | Строит карту. Готовит шаг к взятию: материалы, кто отвечает в бизнесе |
| Техлид потока | Каркас и главный объект — дело взыскания |
| Агент | По просьбе аналитика: материалы в текст (С), выжимки встреч (Т), черновик карты (Т) |

Ворота: материалы не правятся; структуру карты меняет только аналитик.
Этап пройден: у шага есть материалы и роль в бизнесе, аналитик поставил «Готов к взятию».

## 2. Взятие шага

Статус: Готов к взятию → Разбор.

| Кто | Что делает |
|---|---|
| Разработчик — **РЕШАЕТ** | Берёт шаг сам. Один человек, максимум двое |
| Тестировщик | Может встать напарником |
| Аналитик | Подсказывает, с чего начать |
| Агент | Показывает, что свободно и что о шаге уже известно (Л) |

Ворота: лимит шагов на человека; шаг должен быть «Готов к взятию».
Этап пройден: `kb take PM-XX` прошёл.

## 3. Разбор шага

Статус: Разбор.

| Кто | Что делает |
|---|---|
| Разработчик | Своими словами: зачем шаг бизнесу, вход, выход, сущности, исключения, что в MVP |
| Тестировщик | Правила, исключения, реальные примеры |
| Аналитик | Отвечает, если ответ есть в материалах |
| Техлид потока | Помогает со сложными местами |
| Дежурный по знаниям | Склеивает дубли вопросов |
| Агент | Ищет материалы и прошлые ответы (С). Говорит, чего не хватает по критерию глубины (Т). Слова человека записывает после его «да» (С). В RAG идёт туда, куда скажет человек |

Ворота: факт — только с источником; коммит — только после «да».
Этап пройден: владелец сказал «мне достаточно, чтобы писать спецификацию» — `kb step enough`.

## 4. Вопросы и ответы

Статус: Разбор · ждёт ответов ⇄ Разбор.

| Кто | Что делает |
|---|---|
| Разработчик — **РЕШАЕТ** | «Задаём» или «ответ знаю сам». Подтверждает закрытие вопроса |
| Аналитик — **РЕШАЕТ** | Сортирует каждый новый вопрос по «кто отвечает». Собирает пакет, ведёт созвон |
| Бизнес | Отвечает на созвоне или в пакете |
| Дежурный по знаниям | Утром и в 15:00: дайджест, сроки, вопросы без движения |
| Агент | Предлагает формулировку и кому задать (С). Ищет дубли (С). Разбирает расшифровки встреч в ответы (Т) |

Ворота: вопрос — только после «задаём»; полный список изменений строит инструмент.
Этап пройден: блокирующие вопросы закрыты или стали допущениями.

## 5. Сверка с бизнесом

Статус: Сверка с бизнесом.

| Кто | Что делает |
|---|---|
| Разработчик — **РЕШАЕТ** | «Мне достаточно, чтобы писать спецификацию» |
| Аналитик | Проводит сверку шага с бизнесом |
| Бизнес — **РЕШАЕТ** | «Да, мы так работаем» — или поправляет |
| Агент | Готовит по шагу список «так ли вы работаете» (С) |

Ворота: в сверку — когда блокирующие вопросы закрыты или стали допущениями. Иначе — только с причиной.
Этап пройден: бизнес подтвердил, итог сверки записан в шаг.

## 6. Нарезка и приёмка

Статус: Нарезка → Приёмка → Декомпозиты в работе.

| Кто | Что делает |
|---|---|
| Разработчик — **РЕШАЕТ** | Режет шаг на независимые декомпозиты от боли бизнеса |
| Тестировщик | Привязывает случаи к декомпозитам |
| Техлид потока | Пересечения шагов; с аналитиком — роадмап |
| Архитектор недели — **РЕШАЕТ** | Принимает шаг и нарезку на встрече |
| Агент | Подсвечивает пересечения шагов и зависимости по входу и выходу (Т) |

Ворота: порядок статусов; назад — только с причиной.
Этап пройден: архитектор недели принял нарезку.

## 7. Спека

Статус декомпозита: Нарезан → Спека.

| Кто | Что делает |
|---|---|
| Разработчик | Пишет спеку вместе с агентом |
| Тестировщик | Эталон: случаи с ожидаемым результатом |
| Техлид потока | Модули и контракты между ними |
| Архитектор недели — **РЕШАЕТ** | Ревью спеки: согласована ли с другими шагами |
| Агент | Черновик спеки из шага (Т). Сверка спеки с фактами базы (Т) |

Ворота: нет кода без принятой спеки. Ранний срез — только с причиной.
Этап пройден: архитектор недели принял спеку.

## 8. Код и ревью

Статус декомпозита: Сборка → Ревью → Приёмка → Готово.

| Кто | Что делает |
|---|---|
| Разработчик — **РЕШАЕТ** | Код по TDD, MR. Что и когда коммитить — решает сам |
| Тестировщик | Проверка по эталону; новые случаи с боя |
| Техлид потока | Ревью по схемам, а не по каждой строке |
| Архитектор недели | Приёмка декомпозита |
| Агент | Код и тесты по просьбе (Т). Draft MR — после «да» (Л) |

Ворота: тесты по эталону; слить MR через ИИ — никогда.
Этап пройден: декомпозит в «Готово».

## Всегда

- Штурман в любой момент: «ты здесь, дальше вот это, вот почему». Коротко, модель Л.
- Руководитель раз в неделю видит активность по git и правит процесс на ретро.
- Ранний срез: пока шаг в разборе, один декомпозит можно отдать в код. Условие — всё неподтверждённое оформлено принятыми допущениями.

## Не подтверждено владельцем

- Роль бизнеса на этапе кода.
- «Ждёт ответов» — признак или статус.
- Сортировка вопросов аналитиком.
- Пакет для бизнеса с колонкой «Ответ».
- Перекрёстное чтение чужих шагов вместо смены владельцев.
