# Форматы базы знаний

Всё, что проверяет инструмент, описано здесь. Формат простой, чтобы слабая модель писала его без ошибок, а `kb check` проверял его без модели.

Пути ниже — от папки `kb/`. Где что лежит — `AGENTS.md`, раздел «Где что лежит».

## 1. Факт

Одна строка списка:

```
- <текст> (ист: <источник>; <статус>)
```

Пример:

```
- Первое уведомление уходит в течение 5 рабочих дней после формирования списка должников (ист: materials/2026-10-01-reglament.md:4; подтверждено)
```

### Статус — одно из четырёх

| Статус | Когда |
|---|---|
| `подтверждено` | Материал или человек, который сам делает эту работу, говорит это прямо |
| `оценка` | «Примерно», «наверное», «думаю»; ответ RAG; решение со встречи, которое ещё не подтвердил тот, кто решает |
| `допущение A-NNN` | Команда приняла допущение, есть объект A |
| `противоречие` | Два источника по-разному описывают одно и то же **сейчас**. Пишутся оба факта, каждый со своим источником |

Разница между «как сейчас» (ручная работа) и «как будет» (кнопка в продукте) — **не противоречие**. «Как будет» пишется в разделе «Как будет» и не считается фактом.

### Источник — одна из пяти форм

| Форма | Пример | Что проверяет инструмент |
|---|---|---|
| Строка материала | `materials/2026-10-01-reglament.md:4` или `:4-5` | Файл есть, строки есть |
| Ячейка таблицы | `materials/vygruzka.xlsx#Лист1!B4`; для CSV — номер строки | Файл и лист есть |
| Слова человека | `со слов Разработчик-1, 2026-10-17` или `со слов начальник абонентского отдела через Аналитик, 2026-10-16, созвон` | Кто — есть в `team.md` (человек пула или роль бизнеса). Дата — настоящая и не в будущем |
| Ответ на вопрос | `Q-001` | Вопрос есть и закрыт ответом |
| Решение | `D-001` | Решение есть. Если оно «предложено» — статус факта не выше `оценка` |

**Не источник:** «ИИ», «агент», «модель», «GLM», «Qwen», «RAG», «по опыту», «очевидно». Ответ RAG сначала сохраняется файлом в `materials/ai/`. Тогда на него можно сослаться, но статус будет не выше `оценка`.

### Слабая модель пишет иначе — инструмент поправит

`kb fact` принимает близкие формы и сообщает, что поправил:

```
ПОПРАВЛЕНО: «(источник: … , подтверждено)» → «(ист: …; подтверждено)»
ПОПРАВЛЕНО: «confirmed» → «подтверждено»
ПОПРАВЛЕНО: латинская «о» в слове «пoдтверждено» → кириллическая
```

Смысл инструмент не угадывает. Нет источника, нет статуса или неизвестный человек — отказ с подсказкой (`tools/tests/oshibki.md`).

## 2. Шаг карты

Файл `context/process/PM-XX-<slug>.md`. Пример — `tools/tests/fixture/context/process/PM-02-pervoe-uvedomlenie.md`.

### Шапка

```
---
id: PM-02
шаг: Первое уведомление должника
статус: Разбор
владелец: Разработчик-1
напарник: —
людей: 1
приоритет: 2
системы: [SYS-01]
достаточно для спеки: —
---
```

| Поле | Кто меняет | Как |
|---|---|---|
| `статус` | Владелец; на приёмке — архитектор недели | `kb step status PM-02 <статус>`; назад — только с `--reason` |
| `владелец`, `напарник` | Сам человек | `kb take PM-02`; инструмент держит лимит шагов на человека |
| `достаточно для спеки` | Только владелец | `kb step enough PM-02` — окно «да» в OpenCode. Инструмент пишет `Разработчик-1, 2026-10-18` |
| `приоритет`, `людей` | Аналитик | `kb step set` |

### Статусы

```
Черновик → Готов к взятию → Разбор → Сверка с бизнесом → Нарезка → Приёмка → Декомпозиты в работе → Готово
```

- Вперёд — только по одному. Назад — с причиной. Причина пишется в «Историю статуса» и видна в отчёте архитектору и руководителю.
- Из «Разбора» дальше — только когда заполнено `достаточно для спеки`. Это жёсткие ворота.
- В «Сверку» с открытыми блокирующими вопросами — можно, но только с причиной.
- «Ждёт ответов» инструмент показывает сам: `Разбор · ждёт ответов: 3 (бизнес 2, смежник 1)`. Руками этот статус не ставят.

### Разделы — по порядку

| Раздел | Что | Факты с источником |
|---|---|---|
| `Коротко` | 4 строки человеческим языком: что делает, зачем бизнесу, вход, выход. **Пишет владелец своими словами.** Агент может предложить текст, но это и есть проверка понимания | Нет: это пересказ разделов ниже |
| `Объём` | Таблица частей шага: MVP / позже; ручной / автоматизируем / вне системы | Да, в колонке «Источник» |
| `Зачем бизнесу` | Какую боль снимает шаг, числами | Да |
| `Вход` | Что приходит, откуда, как часто | Да |
| `Выход` | Что уходит, куда, кому | Да |
| `Сущности` | Таблица: сущность, поле, откуда берётся, источник | Да |
| `Состояния` | Как меняется главный объект на шаге | Да |
| `Исключения` | Что идёт не по правилам, с реальным примером | Да |
| `Как сейчас` | Действия людей сегодня, по порядку | Да |
| `Как будет` | Намерения: как это будет в продукте. Не факты | Нет. Формат: `- <текст> (предложил <кто>, <дата>)` |
| `Заметки` | Мысли к спеке и нарезке. Не свалка: у каждой есть вид и следующий шаг | Нет. Формат ниже |
| `Нарезка` | Декомпозиты — заполняет владелец в «Нарезке» | — |
| `Приёмка` | Архитектор недели | — |
| `История статуса` | Переходы с причиной. Пишет только инструмент | — |

Вопросов в файле шага нет. Их список по шагу — сгенерированная страница `journal/views/PM-02.md`.

### Критерий глубины разбора

Инструмент считает его сам (`kb step gaps PM-02`): по каждому пункту — пусто, только оценки или есть подтверждённое.

1. Назначение для бизнеса — `Зачем бизнесу`
2. Вход — `Вход`
3. Выход — `Выход`
4. Главные сущности и их поля — `Сущности`
5. Состояния — `Состояния`
6. Исключения — `Исключения`
7. MVP или позже — `Объём`

Это подсказка штурмана, а не ворота. Решает разработчик: последний вопрос разбора — «тебе достаточно, чтобы писать спецификацию?».

### Заметка

```
- [к спеке] Уведомление ставим в очередь, а не шлём сразу (Разработчик-1, 2026-10-17) → дальше: обсудить при нарезке
```

Вид: `к спеке`, `к нарезке`, `гипотеза`, `риск`. Без вида и без «дальше» — предупреждение `kb check`.

## 3. Вопрос

Файл `journal/questions/Q-NNN.md`. Все вопросы лежат в одной папке и никуда не переезжают. Меняется только статус.

```
---
id: Q-001
статус: открыт
кто отвечает: бизнес
шаг: PM-02
MVP: да
блокирует: да
автор: Разработчик-1
задаём: Разработчик-1, 2026-10-17
рассортировал: Аналитик, 2026-10-17
откуда: materials/2026-10-01-zapros.md:5
---
# Q-001 С какого срока долга абонент попадает в список должников: 2 месяца или 3 периода?
```

| Поле | Значения | Кто ставит |
|---|---|---|
| `статус` | `открыт` / `ответ найден` / `отвечен` / `стал допущением A-NNN` / `дубль Q-NNN` / `вне системы` | Инструмент по командам; `отвечен` — после «да» автора |
| `кто отвечает` | `бизнес` / `смежник` / `команда` / `аналитик` / `сами` | Автор предлагает, аналитик сортирует |
| `шаг` | Один шаг или список `[PM-02, PM-05]`: вопрос может касаться двух шагов | Автор |
| `MVP` | `да` / `позже` | Автор; вопросы «позже» не попадают в пакет для бизнеса |
| `блокирует` | `да` — шаг не выйдет из «Разбора» без ответа или допущения | Автор |
| `задаём` | Кто и когда сказал «задаём» | **Только `kb ask send`** — после окна «да» |
| `рассортировал` | Пусто — вопрос в ленте новых у аналитика | Аналитик: `kb q sort` |
| `откуда` | Что вызвало вопрос: строка материала или «со слов …» | Автор. Без этого поля вопрос не создаётся |

«Кто отвечает» заменяет прежний «тип»:

| Значение | Что значит | Что дальше |
|---|---|---|
| `бизнес` | Знает только заказчик | Аналитик берёт в пакет или на созвон |
| `смежник` | Владелец другой системы или интеграции | Автор спрашивает напрямую |
| `команда` | Нужно решение пула | Техлид или архитектор недели |
| `аналитик` | Вопрос скоупа | Аналитик |
| `сами` | Ответ, скорее всего, есть в материалах | Автор ищет сам |

Разделы: `Контекст`, `Что уже знаем` (факты с источником), `Подписчики`, `Ответ`.

`Ответ` — факт с источником и две служебные строки:

```
- В список должников попадают абоненты с долгом за 3 и более расчётных периода (ист: со слов начальник абонентского отдела через Аналитик, 2026-10-18, созвон; подтверждено)
Закрыл: Разработчик-1, 2026-10-18
Записан в: PM-02#Вход
```

`вне системы` закрывает вопросы пачкой с одной причиной: `kb q out Q-003 Q-007 "считает ML, не наш контур"`.

### Предложенный, но не заданный вопрос

Живёт в `.kb/questions/`, то есть только у человека. Это черновик в чате, а не запись в журнале. В журнал он попадает только через `kb ask send` после окна «да». Разработчик ответил сам — агент пишет его слова фактом с источником «со слов», а черновик вопроса удаляет.

## 4. Решение

Файл `journal/decisions/D-NNN.md`. Пример — `tools/tests/fixture/journal/decisions/D-001.md`.

```
---
id: D-001
статус: предложено
предложил: Разработчик-2, встреча 2026-10-16
кто решает: Архитектор недели
принял: —
откуда: materials/meetings/2026-10-16-razbor.md:7
шаг: PM-02
---
```

- `предложено` → `принято` или `отклонено`. Ставит только тот, кто записан в `кто решает`.
- Из расшифровки встречи агент делает только `предложено` и только с говорящим.
- Пока решение `предложено`, факт со ссылкой на него — не выше `оценка`.

## 5. Находки не-владельца шага

Файл `context/process/notes/PM-XX/<логин>.md`. Логин — латиницей, часть почты до `@` из `git config user.email`. Кириллица в именах файлов ломается между macOS и Linux.

```
---
шаг: PM-02
автор: Тестировщик-1
---
# Находки по PM-02

- Абонент с льготой получает SMS, как все (ист: materials/2026-10-01-reglament.md:6; подтверждено) · перенесено: —
```

- Писать в файл может только автор. Это законное место в общем репозитории, а не личный файл: его видит владелец шага.
- Формат фактов тот же, `kb check` проверяет их так же.
- Владелец переносит находку в шаг: `kb notes take PM-02 <логин> <номер строки>`. В шаг строка уходит с источником и пометкой `, нашёл <автор>`. В файле находок пишется `перенесено: PM-02#<раздел>, <дата>`. Строку не удаляют.
- Сессии и черновики вопросов в `notes/` не пишутся — им место в `.kb/`.

## 6. Пакет вопросов для бизнеса

Файл `journal/packages/<дата>-<роль>.md`. Собирает инструмент: `kb package <роль>`.

- Только вопросы с `кто отвечает: бизнес`, `MVP: да`, уже заданные (`задаём` заполнено).
- Группировка по шагам. Колонка «Ответ» пустая.
- Заполненный пакет загружается обратно: `kb package load <файл>`. Ответ привязывается к вопросу с источником `journal/packages/<файл>:<строка>`, статус вопроса — `ответ найден`. Закрывает автор вопроса.

## 7. Глоссарий

`context/glossary.md`. Синонимы — в одной строке, первым идёт основной термин:

```
| ПИНФЛ | ЖШШИР | Персональный идентификационный номер физического лица |
```

Новое слово похоже на термин из глоссария — агент спрашивает: «это одно и то же?», а не заводит второй термин.

## 8. Сгенерированное

Пишет только инструмент или CI. Руками не правят, агент в эти файлы не пишет. Конфликт в git — пересобрать: `kb views`.

| Файл | Что |
|---|---|
| `journal/views/PM-XX.md` | Вопросы шага: открытые, ждут ответа, закрытые; у каждого — «кто отвечает» |
| `journal/views/all.md` | Сверху — «Новые, не рассортированы» (лента аналитика). Ниже — все вопросы по «кто отвечает» и по шагам |
| `journal/reports/<дата>.md` | Утренний отчёт: все изменения по шагам и людям, новые вопросы и ответы. Строит `kb report morning`, модель только пересказывает |
| `context/process/_deps.md` | Связи шагов по входу и выходу: что блокирует что. Для роадмапа |

## 9. Что не попадает в git

`.kb/` в корне репозитория: сессии, вопросы до «задаём» (`.kb/questions/`), планы коммитов, состояние агента. Инструмент проверяет это в pre-commit и в CI.
