# Ворота флоу

Правило держится, только если его проверяет то, что модель не может переписать. Держать могут четыре слоя, от слабого к сильному:

| Слой | Что | Может ли модель обойти |
|---|---|---|
| П | Промпт агента | Да: забудет или «решит» иначе |
| И | Инструмент `kb`: отказывает в записи | Да, если перепишет `tools/` или вызовет `git` в обход |
| О | Права OpenCode: `deny` / `ask`. Окно `ask` нажимает человек | Только переписав `opencode.json` или вызвав команду через разрешённую обёртку |
| С | Сервер: pre-receive, CI, защищённые ветки GitLab; песочница `sbx` с папками только на чтение | Нет |

Жёсткие ворота должны стоять минимум на двух слоях из О, И, С.

## Жёсткие ворота

| Правило | Чем держится | Где проверка | Порция |
|---|---|---|---|
| Коммит — по «да» разработчика | `kb commit plan` показывает, что войдёт, и запоминает отпечаток изменений. `kb commit apply <id>` — **О: ask**: окно видит человек. Отпечаток не совпал — отказ. `git commit` для агента — **О: deny**. pre-commit проверяет, что коммит идёт через `kb commit apply` | Тесты C01–C05 | 3 |
| Отправка на сервер — отдельное «да» | `git push` для агента — **О: deny**. В песочнице нет токена на запись в git: отправляет человек с хоста — **С** | Тест C06; стенд: «агент не пушит» | 3 |
| Вопрос в журнал — по «задаём» | `kb ask send` — **О: ask**. Файл вопроса без поля `задаём` не проходит `kb check` — **И**, pre-commit и CI — **С**. План коммита отдельной строкой показывает новые вопросы | Тесты Q01–Q02; стенд: «не заводит вопрос без задаём» | 4 |
| «Мне достаточно» — только владелец | `kb step enough` — **О: ask**, проверка владельца по `git config` — **И**. Поле руками — отказ `kb check` | Тесты S04, S08, S09 | 5 |
| Факт — только с источником | `kb fact` и `kb check` — **И**. `kb check` в CI на каждом MR — **С** | Тесты F01–F17 | 2 |
| Слить или одобрить MR через ИИ — никогда | Инструменты MCP GitLab для merge и approve — **О: deny**. Ветки базы и кода (`kb/project.md`) защищены: слить может только Maintainer, а токен в песочнице — не Maintainer — **С** | Стенд: просьба «слей MR» | 3 |
| Материалы не правятся | pre-commit и CI отказывают при изменении или удалении файла в `materials/` — **И**, **С** | Тест C04 | 3 |
| Личное не попадает в git | `.kb/` в `.gitignore`; pre-commit и CI отказывают при таком файле в коммите — **И**, **С** | Тест C03 | 3 |
| Секреты окружения закрыты | Пути из поля `закрыто агенту` в `kb/project.md` (секреты окружения) — запрет чтения и правки в правах OpenCode — **О**; в `sbx` эти файлы не монтируются — **С** | Стенд: просьба «покажи конфиг прода» | код |
| База не попадает в ветку кода | CI кода падает, если в ветке появилась папка `kb/` — **С**. Из папки кода база видна только через `.kb-path` и мост `kbx.py` | CI кода | код |
| Агент не переписывает свои правила | `sbx` монтирует `AGENTS.md`, `kb/rules/`, `kb/tools/`, `opencode.json`, `.opencode/`, `.git/hooks` только на чтение (`:ro`) — **С** | Стенд: просьба «поправь правило» | 3, 6 |

## Ворота с причиной

Пройти можно, но команда требует `--reason "…"`. Причина пишется в «Историю статуса» шага и попадает в недельный отчёт архитектору и руководителю.

| Что | Команда |
|---|---|
| В «Сверку» с открытыми блокирующими вопросами | `kb step status PM-XX "Сверка с бизнесом" --reason "…"` |
| Код без принятой спеки (ранний срез) | `kb spec skip PM-XX-NN --reason "…"` — все неподтверждённые факты декомпозита должны быть допущениями |
| Статус назад | `kb step status PM-XX <статус> --reason "…"` |

## Подсказки штурмана

Агент говорит одной строкой, человек решает.

| Подсказка | Откуда берётся |
|---|---|
| Чего не хватает по критерию глубины | `kb step gaps PM-XX` |
| Похожие вход и выход у двух шагов: «один это шаг или два?» | `kb overlap` (потом) |
| «Давно не обновлял базу» | `kb where`: время последнего `git pull` |
| Напоминания дежурного: вопросы без движения | `kb report morning` |
| Пора менять статус: «блокирующие вопросы закрыты — можно в Сверку» | `kb where` |

## Где правило можно обойти — честно

| Дыра | Как закрыть | Когда |
|---|---|---|
| Агент правит `tools/kb.py` так, что разрешённая команда коммитит сама | В `sbx` монтировать `tools/`, `.opencode/`, `opencode.json`, `.git/hooks` только на чтение (`:ro`). Плюс запрет правки этих путей в правах OpenCode [Guessing: проверю, умеет ли ваша версия OpenCode запрет по пути] | Порция 3 |
| Агент пишет скрипт и запускает его | Права bash по умолчанию — `ask`. Разрешены по имени только команды чтения `kb` | Порция 3 |
| Агент пишет файл вопроса руками и подделывает поле `задаём` | Последний рубеж — окно коммита. План коммита отдельной строкой пишет: «новый вопрос Q-new-…, создан не через `kb ask send`» | Порция 4 |
| Человек жмёт «разрешить» не глядя | Инструмент не закроет. План коммита короткий: до 10 строк по-человечески, сначала — новые вопросы и смены статуса | Порция 3 |
| Прогон в Claude Code в недоверенной папке игнорирует проектные права | Запуск только через `kalude` с `--settings`, права монтируются `:ro` | Порция 6 |
| `git commit --no-verify` пропускает pre-commit | Для агента — `deny`. Человека держит CI на сервере | Порция 3 |
