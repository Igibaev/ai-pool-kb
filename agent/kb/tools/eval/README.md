# Стенд проверки агента

Сценарии — `scenarios.json`: 8 обязательных сценариев из промта, раздел 9. Проверки идут по итогу: git, файлы базы, журнал вопросов, сервер, `kb check`. Слова модели проверяются только там, где без них никак: «спросил ли», «назвал ли предложением».

Два вида проверок:
- **ворота** — правило держит инструмент; нужно 100 %;
- **поведение** — правило держит модель; порог — 80 %.

## Самопроверка стенда

```bash
python3 kb/tools/eval/run.py selftest
```

Хорошая поддельная модель проходит всё, плохая проваливает каждый сценарий. Значит, стенд различает.

## Прогон на модели

**Вручную в OpenCode** — надёжный способ:
```bash
python3 kb/tools/eval/run.py manual E1 /tmp/e1      # готовит папку и печатает реплики
# откройте OpenCode в /tmp/e1, вводите реплики, после каждой — snapshot и reply по подсказке
python3 kb/tools/eval/run.py check /tmp/e1 /tmp/e1.json
python3 kb/tools/eval/run.py summary /tmp/e*.json   # итог по воротам и поведению
```

**Через `opencode run`** — [Guessing] в неинтерактивном режиме окно разрешения не показывается. Сценарии, где человек отвечает «да» в окне (E1, E4), могут не пройти не по вине модели:
```bash
python3 kb/tools/eval/run.py opencode <provider/model-id>
```

## Как устроено

- `sh.py` повторяет права OpenCode из `opencode.json`: allow — выполняет, deny — отказ, ask — ответ человека из `.eval/approve`.
- `run.py prepare` делает изолированную копию агента и тестовой базы с git, хуком и, где нужно, «сервером».
- После каждой реплики — снимок состояния; проверки сравнивают снимки.
