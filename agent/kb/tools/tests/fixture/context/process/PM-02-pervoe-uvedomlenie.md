# PM-02 Первое уведомление должника

## Коротко
Что делает: сообщает абоненту о долге по SMS — первое касание после того, как он попал в список должников.
Зачем бизнесу: абонент платит до претензии, а не после неё; претензия не уходит тому, кто уже заплатил.
Вход: месячная выгрузка должников из биллинга.
Выход: отправленное уведомление с датой, способом и результатом в журнале уведомлений.

## Зачем бизнесу
- Претензии уходят абонентам, которые уже заплатили: платежи приходят с задержкой 1–3 дня (ист: materials/2026-10-01-zapros.md:10; подтверждено)
- В месяц уходит 5–6 тыс. SMS (ист: materials/2026-10-01-zapros.md:7; подтверждено)

## Вход
- Биллинг выгружает должников раз в месяц (ист: materials/2026-10-01-zapros.md:5; подтверждено)
- Должник — абонент с долгом больше 2 месяцев (ист: materials/2026-10-01-zapros.md:5; противоречие)
- Должник — абонент с долгом за 3 и более расчётных периода (ист: materials/2026-10-01-reglament.md:3; противоречие)
- Биллинг на 1С 8.3 менять нельзя, доступны только выгрузки (ист: materials/2026-10-01-zapros.md:17; подтверждено)

## Выход
- Каждое уведомление регистрируется в журнале уведомлений: дата, способ, результат (ист: materials/2026-10-01-reglament.md:9; подтверждено)

## Состояния

## Исключения
- Абонент заплатил за 1–3 дня до рассылки, платёж ещё не дошёл до выгрузки (ист: materials/2026-10-01-zapros.md:10; подтверждено)
- Не слать SMS тем, кто платил за последние 3 дня (ист: D-001; оценка)

## Как сейчас
1. Специалист абонентского отдела рассылает SMS скриптом (ист: materials/2026-10-01-zapros.md:5; подтверждено)
2. Первое уведомление уходит в течение 5 рабочих дней после формирования списка должников (ист: materials/2026-10-01-reglament.md:4; подтверждено)
3. Шлюз SMS принимает пакет номеров одним запросом по HTTP (ист: со слов Разработчик-2, 2026-10-17, ответ на Q-002; подтверждено)

## Как будет
- Список на рассылку проверяется по свежим платежам перед отправкой (предложил Разработчик-1, 2026-10-17)
