# Что инструмент обязан отклонить

Каждая строка станет тестом: «вход → ответ инструмента». Базу для тестов даёт `fixture/` рядом с этим файлом.
Ответ инструмента пишется для человека и для слабой модели: что не так и как поправить, одной-двумя строками.

Вердикт: **ОШИБКА** — запись не проходит. **ПРЕДУПРЕЖДЕНИЕ** — проходит, видно в `kb check`. **ПОПРАВЛЕНО** — инструмент сам привёл к формату.

## Факты (порция 2)

| # | Вход | Вердикт | Ответ инструмента |
|---|---|---|---|
| F01 | `- Должник — долг за 3 периода` | ОШИБКА | Факт без источника и статуса. Нужно: `(ист: <материал:строка или «со слов кто, дата»>; <статус>)` |

## Шаг (порции 2 и 5)

| # | Вход | Вердикт | Ответ |
|---|---|---|---|
| S01 | Раздела «Коротко» нет или в нём меньше 4 строк | ПРЕДУПРЕЖДЕНИЕ | Опишите шаг своими словами: что делает, зачем бизнесу, вход, выход |
| S02 | В «Объёме» часть без «MVP / позже» или без «ручной / автоматизируем / вне системы» | ПРЕДУПРЕЖДЕНИЕ | Отметьте, когда делаем и автоматизируем ли |
| S03 | Заметка без вида или без «→ дальше» | ПРЕДУПРЕЖДЕНИЕ | Формат заметки: `- [к спеке] текст (кто, дата) → дальше: …` |
| S04 | `kb step status PM-02 Нарезка` из «Сверки», а `достаточно для спеки: —` | ОШИБКА | В нарезку — после слов владельца «мне достаточно». Команда: `kb step enough PM-02` |
| S05 | `kb step status PM-02 Нарезка` из «Разбора» | ОШИБКА | Вперёд — только на один статус. Следующий: «Сверка с бизнесом» |
| S06 | `kb step status PM-02 Разбор` из «Нарезки» без `--reason` | ОШИБКА | Назад — только с причиной: `--reason "…"`. Причину увидят архитектор недели и руководитель |
| S07 | В «Сверку» при открытом блокирующем Q-001 без `--reason` | ОШИБКА | Открыт блокирующий вопрос Q-001. Закройте его, оформите допущение или укажите причину |
| S08 | `kb step enough PM-02` от не-владельца | ОШИБКА | «Достаточно» говорит владелец шага: Разработчик-1 |
| S09 | Правка `достаточно для спеки:` руками в файле | ОШИБКА | Поле ставит только `kb step enough`. `kb check` сверяет его с историей подтверждений |
| S10 | `kb take PM-05`, когда у человека уже один шаг в работе при лимите 1 | ОШИБКА | Лимит — 1 шаг на человека. У вас PM-02 в «Разборе» |

## Вопросы (порция 4)

| # | Вход | Вердикт | Ответ |
|---|---|---|---|
| Q01 | Новый файл в `journal/questions/` без поля `задаём` | ОШИБКА | Вопрос попадает в журнал только через `kb ask send` — после «задаём» разработчика |
| Q02 | `kb ask send` без поля `откуда` | ОШИБКА | Откуда вопрос: строка материала или «со слов кто, дата» |
| Q03 | `кто отвечает: бизнес-правило` | ОШИБКА | Значения: бизнес, смежник, команда, аналитик, сами |
| Q04 | `кто отвечает: business` | ПОПРАВЛЕНО | `business` → `бизнес` |
| Q05 | Новый вопрос почти совпадает с Q-001 | ПРЕДУПРЕЖДЕНИЕ | Похож на Q-001. Это тот же вопрос? Можно стать подписчиком |
| Q06 | `статус: отвечен` без строки «Закрыл:» | ОШИБКА | Закрытие подтверждает автор: `kb q close Q-001` |
| Q07 | Перенос файла вопроса в другую папку | ОШИБКА | Вопросы лежат в `journal/questions/` плоско. Меняется статус, файл не двигается |

## Коммит и прочее (порция 3)

| # | Вход | Вердикт | Ответ |
|---|---|---|---|
| C01 | `git commit` от агента | ОШИБКА (права OpenCode: deny) | Коммит — через `kb commit plan`, потом `kb commit apply` по «да» разработчика |
| C02 | `kb commit apply <id>`, а после `plan` изменился файл | ОШИБКА | С момента показа изменилось: `PM-02`. Покажите план заново: `kb commit plan` |
| C03 | В коммите файл из `.kb/` | ОШИБКА | Личные файлы в git не попадают: `.kb/questions/q-porog-dolga.md` |
| C04 | В коммите изменён файл в `materials/` | ОШИБКА | Материалы не правятся. Новая версия — новый файл с датой |
| C05 | В коммите изменён `journal/views/*` руками | ОШИБКА | Списки строит инструмент: `kb views` |
| C06 | `git push` от агента | ОШИБКА (права OpenCode: deny) | Отправку на сервер делает человек |
| C07 | `git remote set-url origin …` от агента | ОШИБКА (права OpenCode: deny) | Доступ не обходим. Нет доступа — скажите человеку |
