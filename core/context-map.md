# Карта модулей и сервисов

## Сервисы
Одна база на сервис. Внутри сервиса — модули с проверяемыми границами.

| Сервис | Зачем отдельно | База | Модули внутри | Runbook |
|---|---|---|---|---|
| | | | | `services/<сервис>/RUNBOOK.md` |

## Модули
| Модуль | Сервис | Чем владеет | Публикует события | Слушает события | Публичный интерфейс |
|---|---|---|---|---|---|

## Правила границ
1. Модуль владеет своими таблицами. Чужие данные — только через интерфейс владельца или событие.
2. Нет транзакций через границу модуля или сервиса. Нужна согласованность — событие с гарантированной доставкой.
3. Между модулями передаются DTO, а не сущности.
4. События — контракты: поля добавляются, но не удаляются и не меняют смысл.
5. Внешние системы — только через адаптеры. Ядро не знает чужих форматов.
6. Нарушение границы ловит проверка в CI, а не ревью.
