# OpenCode со своей моделью

Оболочка работает в OpenCode с любой моделью, которая умеет вызывать инструменты: в своём контуре через vLLM, Ollama, LM Studio или любой сервер с OpenAI-совместимым API.

Модели слабее Claude чаще пропускают шаги, путают формат и сами не загружают нужный скилл. Поэтому для OpenCode работа устроена так, чтобы модели оставалось меньше решать самой:

| Что | Как помогает модели |
|---|---|
| Агент `kb` (`.opencode/agents/kb.md`) | Короткие жёсткие правила работы, низкая температура, лимит шагов. Включён по умолчанию в `opencode.json` |
| Команды `/kb-…` (`.opencode/commands/`) | Текст скилла вставляется прямо в сообщение. Модели не нужно самой решать, какой скилл загрузить |
| Команды записи `kb.py fact`, `new … поле=…`, `set`, `append` | Модель не правит markdown руками: формат и допустимые значения держит скрипт, ошибку он возвращает словом «ОШИБКА» |
| Выжимки `kb.py whoami`, `context`, `similar`, `changes`, `peek` | Меньше читать, меньше шанс потеряться в длинном контексте |
| `kb.py check` | Ловит факты без статуса, похожие на персональные данные строки, битые ссылки, неверные статусы |
| Сжатие контекста (`compaction.prune`) | Старые выводы команд выбрасываются, длинная сессия влезает в окно модели |

## Требования к модели

- **Вызов инструментов (tool calling)** — обязательно. На сервере он должен быть включён. Например, в vLLM это флаги автоматического выбора инструмента и парсера вызовов для вашей модели — смотрите документацию сервера.
- **Контекст** — от 32 тыс. токенов, лучше 64 тыс. и больше. Одна задача: правила, скилл и выжимка шага — это 8–12 тыс. токенов, остальное уходит на работу.
- **Ответ** — от 4 тыс. токенов.
- **Русский язык** — модель должна уверенно писать по-русски.

Подходит ли модель, проверяйте не на глаз, а экзаменом (ниже).

## 1. Подключить модель

Модель подключается один раз на компьютере, а не в репозитории продукта: адреса и ключи в репозиторий не кладём.

1. В OpenCode: `/connect` → **Other** → ID провайдера, например `kontur` → ключ (если сервер без ключа — любая строка).
2. В `~/.config/opencode/opencode.json` (на Windows — `%USERPROFILE%\.config\opencode\opencode.json`):
   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "kontur": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "Модель в контуре",
         "options": { "baseURL": "http://<адрес-сервера>/v1" },
         "models": {
           "<id-модели-на-сервере>": {
             "name": "<как показывать в списке>",
             "limit": { "context": 65536, "output": 8192 }
           }
         }
       }
     },
     "model": "kontur/<id-модели-на-сервере>"
   }
   ```
3. `/models` — выберите модель.

`limit.context` поставьте честно — по настройке сервера. По нему OpenCode решает, когда сжимать контекст.

## 2. Что уже настроено в репозитории

- `opencode.json` — агент `kb` по умолчанию, сжатие контекста, разрешения: `kb.py` и чтение git — без вопросов, `git push`, `reset`, `rm` — с подтверждением.
- `.opencode/agents/kb.md` — правила агента.
- `.opencode/commands/kb-*.md` — команды со вставленным скиллом.
- `AGENTS.md` OpenCode читает сам.

## 3. Как работать

- **Всегда через команды** `/kb-explore PM-04 …`, `/kb-sync утро` и так далее, а не просто словами. Команда гарантирует, что модель увидит нужный скилл целиком.
- **Одна задача — одна сессия** (`/new`). Модели с небольшим окном быстро теряют начало длинной сессии.
- **Перед коммитом смотрите `python3 tools/kb.py check`.** Предупреждения о фактах без статуса и персональных данных у слабой модели появляются чаще.
- **Модель задала вопрос — отвечайте коротко**, вариантом из предложенных.
- **Модель ушла в сторону** — остановите и наберите команду заново с уточнением: «продолжи с шага 4 скилла».

## 4. Экзамен модели

В наборе симуляции (папка `sim/` — в архиве `simulyaciya-kit` или в репозитории пула) есть `sim/exam.py`: два контрольных шага на данных «взыскания» и автоматическая проверка результата.

```
cd sim
python3 build.py                                 # один раз
python3 exam.py prepare explore ../exam-explore  # подготовить папку
# открыть ../exam-explore в OpenCode, выполнить команду из вывода prepare
python3 exam.py grade explore ../exam-explore    # оценка
```

То же для `sync`: утреннее дежурство, поиск дубля и противоречия.

| Экзамен | Что проверяется | Сколько пунктов |
|---|---|---|
| `explore` — разбор PM-04 | Статус «Разбор»; факты из скрипта с источниками; нет фактов без статуса; противоречие «ФИО и дата рождения / ФИО и сумма» записано; вопрос про источник правды заведён; не больше 8 вопросов; чужие файлы не тронуты; всё закоммичено | 12 |
| `sync` — утреннее дежурство | Q-004 склеен с Q-002; автор дубля в подписчиках; противоречие вынесено вопросом; дайджест с «Синхронизировано до»; утром статусы «ждёт бизнес» не ставятся; шаги не тронуты | 9 |

Ориентир: модель годится для работы, если стабильно набирает все пункты в двух-трёх прогонах подряд. Claude и его младшая модель на этих экзаменах набирают все пункты. Модель, которая сдаёт `sync`, но не сдаёт `explore`, можно оставить на дежурство и ответы, а разбор шагов отдать сильной модели.

## Если модель не справляется

| Симптом | Что сделать |
|---|---|
| Не вызывает инструменты, пишет команды текстом | На сервере не включён tool calling или парсер не подходит к модели |
| Пишет по-английски | Проверьте, что выбран агент `kb` (Tab); в нём правило «только по-русски» |
| Теряет шаги в середине | Меньше окно, чем указано в `limit.context`, — поставьте честное значение; одна задача на сессию |
| Правит markdown руками и ломает формат | Напомните: «пиши командами kb.py fact / set / append» |
| Придумывает ID вопросов | `kb.py check` найдёт ссылку на несуществующий объект; ID даёт только `kb.py new` |
| Обрывается на длинной задаче | Увеличьте `steps` в `.opencode/agents/kb.md` или делите задачу: «разбери только Как сейчас и Правила» |
