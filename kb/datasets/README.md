# Золотой датасет

Реальные обезличенные случаи с ожидаемым результатом. Из них берутся цифры для сценариев спек и эталон для проверки кода (`kb/docs/proverka-koda.md`).
Собирают тестировщики скиллом `kb-dataset`.

## Структура
```
kb/datasets/
  PM-04/
    README.md                     матрица покрытия: правило или исключение → случаи → пробелы
    GD-PM-04-001-oplata-posle-vygruzki.md
```

## Шаблон случая
```markdown
---
id: GD-PM-XX-NNN
шаг: PM-XX
тип: <обычный | граница | исключение | с боя | нагрузка>
правило: <раздел и строка шага, которую проверяет случай: PM-XX «Правила», 3>
данные: <реальные — файл и строка в kb/materials/ | синтетические>
статус ожидания: <подтверждено | допущение A-… | ждёт Q-…>
декомпозит: <PM-XX-NN — заполняется при нарезке>
проверка: <модульный тест | контрактный тест | стенд>
---
Вход: <данные, обезличенные>
Ожидаемый результат: <что должно получиться — одно наблюдаемое значение или действие>
Откуда известно: <источник ожидания: правило шага, ответ бизнеса Q-…, документ>
```

## Матрица покрытия — `kb/datasets/PM-XX/README.md`
```markdown
| Правило или исключение (шаг, раздел, строка) | Случаи | Пробел |
|---|---|---|
| Претензия при долге > 10 000 тг («Правила», 2) | GD-PM-04-001, -002, -003 | — |
| Абонент заплатил после выгрузки («Исключения», 1) | — | нет данных: вопрос Q-… |
```

## Правила
- Только обезличенные данные. Персональные данные в `kb/datasets/` — ошибка `kb.py check`.
- Ожидание — только из источника. Нет источника — «ждёт Q-…».
- Если ожидание взято из старого скрипта, а скрипт мог ошибаться, — статус «допущение».
- Каждый случай, найденный на бою и не покрытый сценариями, добавляется сюда с типом «с боя».
