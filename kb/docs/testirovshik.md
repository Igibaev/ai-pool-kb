# Тестировщику: как работать с агентом

Ваша задача до кода — найти, где процесс ломается, и собрать **эталон**: реальные случаи «вход → ожидаемый результат». По этому эталону потом проверяют код (`kb/docs/proverka-koda.md`). Ожидаемый результат — только из источника: правило шага, ответ бизнеса, документ. Нет источника — нет ожидания, есть вопрос.

## Один раз

1. `git config user.name "Имя"` и `git config user.email "рабочая почта"` в папке репозитория.
2. Попросите аналитика добавить вас в `kb/team.md`.
3. Откройте корень репозитория в Claude Code или OpenCode. На Windows вместо `python3` — `python` или `py -3`.
4. Один раз: `pip install pypdf openpyxl py7zr` — чтобы агент читал PDF, Excel и архивы.

## Где вы в руте

| Вариант | Как попасть | Что пишете |
|---|---|---|
| Напарник в руте на двоих | `/kb-take PM-04` — если у рута «людей: 2», вы станете напарником | Свои разделы шага: «Объём и время», «Исключения»; датасет `kb/datasets/PM-04/` |
| Карточка разбора | `/kb-take` — «что взять» → карточка вроде «Исключения по выпискам» | Находки в карточку; в шаг их переносит владелец |
| Сами по себе, рут чужой | — | Датасет через MR владельцу рута |

## Путь — по шагам

| # | Когда | Что сказать агенту | Что получится |
|---|---|---|---|
| 1 | Начало дня | `/kb-next` | Новые ответы, вопросы к вам, что дальше |
| 2 | Рут в «Разборе» | `/kb-explore PM-04` — «я тестировщик» | Агент спрашивает вас про объёмы, пики, исключения, пороги; записывает факты с источником |
| 3 | Правила и исключения в шаге есть | `/kb-dataset PM-04` | Матрица покрытия: правило или исключение → какие случаи нужны → пробелы |
| 4 | Матрица согласована | «Собери случаи по матрице» | Случаи `kb/datasets/PM-04/GD-PM-04-NNN-*.md` с реальными данными из материалов |
| 5 | Ожидания нет в источнике | Ничего — агент заведёт вопрос «Какой результат ожидается, когда …?» | Случай с `статус ожидания: ждёт Q-…` |
| 6 | Сверка с бизнесом прошла | `/kb-dataset PM-04` — «обнови ожидания» | «ждёт Q-…» и «допущение» → «подтверждено» по ответам |
| 7 | Нарезка (`kb-slice`) | «Привяжи случаи к декомпозитам PM-04» | У каждого случая — декомпозит; у каждого декомпозита — хотя бы один случай |
| 8 | Нашли случай на бою | `/kb-dataset` — «новый случай с боя: …» | Случай с пометкой «с боя» и ссылкой на инцидент |

## Какие случаи нужны — агент предложит, вы дополните

| В шаге | Случаи |
|---|---|
| Правило | Срабатывает; не срабатывает |
| Порог, срок, лимит (10 000 тг, 2 месяца, 21:00) | Ровно на пороге, на шаг ниже, на шаг выше |
| Исключение | Реальный пример из материалов |
| Идентификатор | Номер сменился, повторился, пропал, в другом формате |
| Время | Конец дня и периода, выходной, данные пришли с задержкой |
| Деньги | Частичная оплата, переплата, оплата после выгрузки, округление |
| Противоречие двух источников | Случай, где они дают разный результат: ожидание «ждёт Q-…» |
| Объём | Самый тяжёлый день — для нагрузки |

Агент спросит вас: «Где на бою чаще всего ошибаются? Каких случаев не хватает? Какие помните сами?» Случай «из памяти» без данных — не случай: агент заведёт вопрос бизнесу «покажите такой пример».

## Данные для случаев

- Агент берёт реальные строки из материалов по номеру строки и пишет, откуда.
- Персональные данные в датасете — только маской: «Должник 17», `3140590*******`. Даже если в материале настоящие ФИО.
- Реальной строки нет — синтетический случай с пометкой `данные: синтетические`. Ожидание всё равно из источника.
- Ожидание взято из старого скрипта, а скрипт мог ошибаться, — статус «допущение».

## Когда дошло до кода

Подробно — `kb/docs/proverka-koda.md`. Ваша часть:

| Ворота | Что делаете |
|---|---|
| 1. MR в develop | Следите, чтобы тесты разработчика брали случаи из датасета. Нужен новый граничный случай — сначала в датасет, потом в тест |
| 2. Стенд интеграции | Прогон идёт сам. Тест зелёный, а на стенде упало из-за данных — случай со стенда в датасет с пометкой «с боя» |
| 3. Приёмка декомпозита | Проходите случаи `GD-…` декомпозита на стенде вместе с архитектором недели. Все «подтверждено» прошли — декомпозит идёт в канарейку |

Стенда пока нет — раз в день прогоняете датасет руками на машине с доступом к тестовым копиям.

## Новые материалы и встречи

Положите файлы или запись встречи в `kb/inbox/` как есть и скажите: «разбери новые материалы в inbox». Агент сам запустит `kb.py convert`, скажет, какие файлы не прочитаны (сканы), и оформит встречу с саммари.

## Чего не делать

| Не делайте | Почему | Как правильно |
|---|---|---|
| Придумывать ожидаемый результат | Эталон, придуманный тестировщиком, проверит код на ваше мнение, а не на правило бизнеса | Нет источника — вопрос |
| Класть настоящие ФИО и ИИН в датасет | `kb.py check` остановит коммит; датасет читает весь пул | Маски того же вида |
| Собирать случаи до матрицы покрытия | Получится 30 похожих случаев и ни одного на пороге | Сначала матрица, потом данные |
| Ждать конца разбора, чтобы начать | Пороги и исключения видны сразу | Подключайтесь в «Разборе», ожидания уточните после сверки |
