# Материалы бизнеса

Сырые материалы, из которых собирается карта процессов: скрипты, Excel, выгрузки, регламенты, переписка, записи интервью, прототипы.

## Правила
- Только обезличенные данные. Персональные данные клиентов сюда не попадают.
- Материалы не правятся. Новая версия — новый файл с датой в имени.
- Факт в карте процессов ссылается на материал: путь к файлу и место — лист, строка, функция.

## Структура
```
kb/materials/
  scripts/      скрипты, которыми работают сейчас
  files/        Excel, CSV, выгрузки систем
  docs/         регламенты, инструкции, договоры
  meetings/     расшифровки всех встреч и саммари к ним (<дата>-<с-кем>.md + .summary.md); _index.md — список, генерирует kb.py index; планы созвонов <дата>-<роль>-plan.md;
                сверка рута <дата>-sverka-PM-XX.md (без него рут не нарезают)
  answers/      письменные ответы бизнеса: <дата>-<роль>.md (kb-answer)
  prototypes/   прототипы и макеты от бизнеса
```

Если файл нельзя хранить в репозитории (большой или с ограничением доступа), здесь лежит файл-ссылка: где лежит оригинал, кто владелец, дата.

## Встречи

Записи встреч — с бизнесом, со смежниками, внутренние — кладут в `kb/inbox/` как есть: `.txt`, `.md`, `.docx`, `.vtt`, `.srt`. `kb.py convert` помечает похожие на расшифровку: «ПОХОЖЕ НА РАСШИФРОВКУ ВСТРЕЧИ» (метки говорящих, метки времени, субтитры, слова «встреча», «созвон», «транскрибация» в имени).

Один и тот же шаг во всех скиллах:

1. Агент не уверен, что файл — встреча, — один вопрос человеку списком: «Это расшифровки встреч? Отметьте лишние».
2. `python3 kb/tools/kb.py new meeting <с-кем> из=kb/inbox/_md/<файл>.md "с кем=<роли или команда>" тема="<одной фразой>" шаги=[PM-04]`. Дата берётся из файла; не нашлась — `дата=ГГГГ-ММ-ДД`, спросить человека. Дату копирования не подставлять. Команда кладёт расшифровку в `kb/materials/meetings/<дата>-<с-кем>.md`, заготовку саммари рядом и строку в `kb/inbox/_razobrano.md`.
3. Заполнить саммари по шаблону (`meetings/_template.summary.md`): Кратко, Цифры, Договорились, Не ясно, Что дальше. Каждый пункт — с номером строки расшифровки. Показать саммари человеку.
4. Дальше — по разделу «Что дальше»: ответы на вопросы журнала — `/kb-interview` режим Б; структура карты — `/kb-map`; факты для шагов — владельцам, `/kb-explore`.

Саммари — навигация, не источник фактов. Факт в шаге ссылается на строку **расшифровки**. `<с-кем>` — роль или команда латиницей (`smezhniki-bki`, `yurist`), без имён людей. Список встреч — `meetings/_index.md`, его собирает `kb.py index`.

## В каком виде приносить материалы (папка `kb/inbox/`)

Кладите файлы **как есть**: PDF, DOCX, PPTX, XLSX, CSV, архивы ZIP и 7z, расшифровки `.txt`, `.vtt`, `.srt`. Команда `python3 kb/tools/kb.py convert` переводит их в текст с номерами строк в `kb/inbox/_md/`, оригиналы не трогает. Такой текст одинаково читает любая модель, на него можно сослаться «файл, строка 12».

| convert не прочитает | Что сделать |
|---|---|
| PDF-скан (картинка страницы) | Попросить у бизнеса текстовую версию или `convert --ocr` (нужен `ocrmypdf` с языками rus и kaz; цифры после распознавания сверять с оригиналом) |
| `.doc`, `.xls`, `.ppt`, `.rar` | Пересохранить в `.docx`, `.xlsx`, `.pptx`, `.zip` |
| Картинки, скриншоты | Рядом — описание экрана словами в `.md` |
| Аудио, видео | Сначала расшифровка в текст |

Нужные библиотеки (необязательные, ставятся один раз): `pip install pypdf openpyxl py7zr`. Без них `convert` скажет, чего не хватает.

Советы, как сделать материал удобнее:

| Что принёс бизнес | Лучший формат | Можно, но хуже | Как подготовить |
|---|---|---|---|
| Таблица, выгрузка из 1С, Excel | **CSV в UTF-8**, первая строка — заголовки, один лист — один файл | `.xlsx` (агент прочитает через `kb.py peek`, если установлен `openpyxl`) | Каждый лист «Сохранить как CSV UTF-8». Формулы — значениями. Объединённые ячейки разъединить. Большую таблицу (тысячи строк) — выборкой на 200–500 строк с исключениями плюс файл-описание: сколько строк всего, за какой период, что значат колонки |
| Скрипт, макрос, запрос | **Как есть**: `.py`, `.sql`, `.js`, `.bsl` (модули 1С выгрузкой в текст), `.bas` | Скриншот кода — нет | Один файл — один скрипт. Комментарием в начале — кто запускает, как часто |
| Регламент, инструкция, договор | **Markdown или TXT**, разделы заголовками | `.docx`, `.pdf` с текстовым слоем — Claude прочитает, слабой модели лучше Markdown | Сконвертировать в `.md` (например, `pandoc файл.docx -o файл.md`), оригинал положить рядом |
| Интервью, встреча | **Расшифровка в `.md`**: дата, роль говорящего, вопрос — ответ | Аудио и видео — нет, агент их не читает | Прогнать запись через транскрибацию, затем вычистить имена. Вверху: дата, кто проводил, роли участников |
| Переписка в мессенджере, почта | **TXT или MD**, экспорт чата | Скриншоты переписки | Экспорт чата в текст, только нужная ветка, имена клиентов заменить |
| Экран текущей системы, макет | **PNG плюс `.md`-описание**: какие поля, что человек на экране решает | Только картинка — слабая модель без зрения её не поймёт | Рядом с картинкой — описание экрана словами |
| Запрос бизнеса, письмо | **`.md`** в `brief/` как есть | — | Ничего не переписывать, только обезличить |

### Шапка каждого текстового файла

Три строки вверху — и агенту не придётся гадать, откуда материал:

```
# <Что это>
Источник: <кто дал, роль, отдел> · Дата: <ГГГГ-ММ-ДД> · Обезличено: да
Период данных: <если выгрузка>
```

### Имена файлов

Латиницей, с датой и одной темой: `files/vypiska-2026-09-12.csv`, `meetings/2026-10-09-buhgalteriya.md`, `docs/reglament-vzyskaniya-2026-03.md`. Без пробелов, без «Новый документ (3).docx».

### Персональные данные — до `kb/inbox/`, не после

ФИО клиентов, ИИН, ПИНФЛ, телефоны, номера карт и счетов, паспорта заменяются **до того, как файл попал в репозиторий**: из истории git их потом не удалить без переписывания истории. Заменять на вымышленные значения того же вида (`Клиент 17`, `3140590*******`), чтобы правила и форматы остались видны. `kb.py check` предупреждает, если видит похожие на персональные данные строки.

### Большие файлы

Больше 20 КБ — агент делает рядом выжимку `<имя>.summary.md`, и дальше все читают её. Больше нескольких мегабайт или с ограничением доступа — в репозиторий не кладём, вместо файла — ссылка `.md`: где лежит оригинал, кто владелец, дата.
