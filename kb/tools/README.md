# Инструменты

`kb.py` — проверка и обслуживание базы знаний и журнала. Только стандартная библиотека Python 3.9+. Полный список — `python3 kb/tools/kb.py --help`.

| Команда | Что делает | Кто запускает |
|---|---|---|
| `check` | Проверяет шапки, формат ID, уникальность, статусы, ссылки на несуществующие объекты, шаги без узла на схеме, просроченные допущения, похожие на персональные данные строки | Агент перед коммитом и `kb.py push`; CI на каждом push в `context` |
| `index` | Пересобирает `kb/context/process/_index.md` (с карточками), `kb/journal/_index.md`, `kb/materials/meetings/_index.md` и рисует карту (`map`) | CI; человек — только для просмотра, в коммит не добавляет |
| `new question <slug> [поле=… "Раздел=…"]` | Создаёт вопрос с временным ID `Q-new-<slug>`, сразу заполненный | Агент (`kb-ask`, `kb-explore`) |
| `new assumption <slug> …` | Создаёт допущение `A-new-<slug>` | Агент (`kb-assume`) |
| `new decision <slug> …` | Создаёт решение `D-new-<slug>` | Агент (`kb-decide`) |
| `new risk <slug> …` | Создаёт риск `R-new-<slug>` | Агент (`kb-risk`) |
| `new step <slug> шаг="…" ["порядок=N из M" системы=[…] "Зачем этот шаг бизнесу=…"]` | Создаёт файл шага `PM-XX` по шаблону, номер — следующий свободный; главный объект берёт из `_map.md` | Аналитик (`kb-map`) |
| `new system <slug> система="…" ["Роль в процессе=…"]` | Создаёт файл системы `SYS-XX` | Аналитик (`kb-map`) |
| `new card PM-XX <slug> заголовок="…" "Что выяснить=…" …` | Создаёт карточку шага `PM-XX-KNN` | Владелец рута, аналитик (`kb-explore`, `kb-map`) |
| `cards [PM-XX]` | Открытые карточки рутов в «Разборе» по приоритету или все карточки рута | Любой (`kb-take`) |
| `take` / `release PM-XX-KNN` | Взять или вернуть карточку: рут в «Разборе», лимит карточек из `kb/team.md` | Любой |
| `fact PM-XX-KNN "<Раздел шага>" …` | Находка в карточку; пишет только взявший | Взявший карточку |
| `card accept` / `card return PM-XX-KNN` | Перенести находки карточки в шаг / вернуть в работу с причиной | Владелец рута |
| `new meeting <с-кем> из=<файл> "с кем=…" тема="…" [шаги=[…]]` | Расшифровка встречи → `kb/materials/meetings/<дата>-<с-кем>.md`, заготовка саммари, строка в `kb/inbox/_razobrano.md` | Агент (раздел «Встречи» в `kb/materials/README.md`) |
| `convert [kb/inbox] [--ocr] [--force]` | Материалы в текст: PDF, DOCX, PPTX, XLSX (+CSV по листам), ZIP, 7z, `.vtt`, `.srt` → `kb/inbox/_md/`; помечает сканы и расшифровки встреч; оригиналы не трогает | Агент первым шагом при новых материалах |
| `map apply [план] [--check]` | Пересборка карты по плану «Было → Станет» | Аналитик (`kb-map` режим 2) |
| `map sync` | После ручной правки таблицы «Шаги»: создать недостающие шаги, обновить порядок | Аналитик |
| `upgrade --from <шаблон> [--ref main]` | Обновить инструмент из шаблона, знания не трогает | Руководитель или техлид |
| `show Q-…` | Вопрос и ответ целиком для экрана | Агент |
| `team add/set/remove` | Состав команды с «Историей состава» | Аналитик |
| `note` / `resume` | Заметка сессии / что осталось от прошлой сессии | Агент |
| `fact <PM-XX\|SYS-XX> "<Раздел>" "<текст>" "<источник>" <статус>` | Дописывает факт в формате `текст (источник, статус)` с проверкой статуса | Владелец шага или системы |
| `set <ID\|файл> поле=значение … [--force "причина"]` | Меняет поле шапки с проверкой значений. Статус рута — только на следующий; назад или через статус — `--force`, причина пишется в «Приёмка рута» | Хозяин объекта; архитектор на приёмке |
| `append <ID\|файл> "<Раздел>" "<строка>"` | Дописывает строку в раздел: Подписчики, Уточнения, История, Ответ, Чем закрыто, Приёмка рута | Любой — в разделы, куда можно дописывать |
| `whoami` | Кто я: роли, режим, мои руты и лимит, вопросы, «Ответы ждут переноса в ваш шаг», для аналитика — «Ответы без хозяина», допущения, риски | Любой (`kb-next`) |
| `ready` | Руты, готовые к взятию, по приоритету; «Ищут напарника»; сколько у вас в работе | Любой (`kb-take`) |
| `ready-check <PM-XX>` | Чего не хватает шагу до «Готов к взятию»; подсказка «людей» по четырём признакам | Аналитик (`kb-map` режим 3) |
| `take <PM-XX\|SYS-XX>` | Взять рут (проверяет готовность и лимит; второй на `людей: 2` — напарник) или систему. Печатает готовую команду коммита | Любой (`kb-take`) |
| `release <PM-XX\|SYS-XX> "<почему>"` | Вернуть рут в «Готов к взятию», выйти из пары или отпустить систему | Владелец или напарник |
| `context <PM-XX\|SYS-XX>` | Всё о шаге одной выжимкой: кто работает и владелец ли он, место на карте, файл шага и заполненность, журнал по руту, глоссарий, нарезка других рутов | Агент вместо чтения пяти-семи файлов |
| `similar "<текст>" ["<синонимы>"]` | Кандидаты среди вопросов, допущений, решений, рисков и строк фактов — по словам | Агент перед новым вопросом и при поиске дублей |
| `changes --since <хеш\|дата> [--only <путь>]` | Коммиты, новые объекты журнала, изменённые строки | Дежурный (`kb-sync`) |
| `peek <файл> [строк]` | Паспорт большого файла: колонки, частые значения, первые строки с номерами | Агент перед разбором выгрузки |
| `refs <ID>` | Все упоминания ID: контекст, спеки, тесты, код | Агент, когда меняется допущение или решение |
| `map` | Рисует `_map.svg` и интерактивную `_map.html`. Вызывается из `index` | CI; для просмотра — любой |
| `assign-ids` | Присваивает постоянные номера временным ID, заменяет их во всех файлах, пишет `kb/journal/_renames.tsv` | Только CI в `context`; в соло — через `after-merge` |
| `after-merge` | `assign-ids` + `index` — то, что делает CI | CI; в соло — человек после коммита, затем коммит «kb: номера и сводки» |
| `activity [--since <дата\|хеш\|7д>] [--until] [--who <имя>] [--html <файл>]` | Кто что делал за период и сигналы процесса — по истории git | Руководитель (`kb-activity`) |
| `report [--with-materials]` | Архив `kb-report-<дата>.zip`: база знаний, kb/FEEDBACK.md, история git | Пилот |

Сгенерированные файлы — `_index.md`, `_map.svg`, `_map.html`, `kb/journal/_renames.tsv` — люди в коммиты не добавляют. `kb/inbox/_md/` в git не идёт (`.gitignore`).

Необязательные библиотеки: `pip install pypdf openpyxl py7zr` — для PDF, Excel и 7z в `convert`. Без них команда скажет, чего не хватает.

## Что делает CI (`.gitlab-ci.yml`, `.github/workflows/kb.yml`)

**На каждом push в `context`:** `python3 kb/tools/kb.py check`. Главная проверка — раньше, в `kb.py push`: с ошибками он не отправляет.

**После каждого push в `context`** (строго по одному: `resource_group` в GitLab, `concurrency` в GitHub): `python3 kb/tools/kb.py after-merge`, затем коммит `kb: номера и сводки [skip ci]` токеном `KB_PUSH_TOKEN`. Ссылки на `X-new-…` в неотправленных коммитах чинятся при следующем прогоне по `kb/journal/_renames.tsv`.

Почему номера присваивает CI, а не человек: двое, создавших вопрос одновременно, иначе получат одинаковый номер. Последовательный запуск в `context` гарантирует, что номер уникален. Настройка GitLab — `kb/docs/setup.md`.
