# Приёмка рута

Приёмку делает архитектор недели. Агент готовит проверку и черновик вывода, решение принимает человек.

## 1. Подготовка

1. `git pull --rebase`. Убедись, что `git config user.name` совпадает с полем «архитектор недели» в `team.md`. Если нет — сделай только отчёт для человека, в файл не пиши.
2. Статус рута — «Приёмка». Если нет — скажи, на каком он этапе, и остановись.
3. `python3 tools/kb.py context PM-XX` — файл шага, место на карте, журнал по руту, нарезка других рутов. Плюс `core/domain-model.md` и `core/context-map.md`.

## 2. Что проверить

### Полнота
- Все разделы шаблона заполнены или явно помечены, почему пусто.
- Готовность шага (можно на сверку и в нарезку): известно, кто и в чём работает с объектом; сколько этого и как часто — числами; где теряются время и деньги — числами; какие данные рождаются и кто источник правды; исключения с реальными примерами.
- Объёмы и время — числами. Боль — числами.
- Есть исключения с реальными примерами и случаи в `datasets/PM-XX/`.

### Качество фактов
- У каждого факта есть источник и статус. Выбери 3–5 фактов и открой источник: действительно ли там так написано.
- Нет фактов «из опыта».
- Противоречия либо разрешены, либо по ним есть вопрос типа «решение».

### Нарезка
- Каждый декомпозит убирает боль из раздела «Боль».
- Размер 1–3. Больше — вернуть на нарезку.
- Зависимости записаны явно, циклов нет.
- Ничего общего для нескольких рутов не нарезано внутри рута — оно в `PM-00`.
- Нет пересечений с декомпозитами других рутов.

### Журнал
- Нет открытых вопросов, которые блокируют декомпозиты этого рута без допущения.
- У каждого открытого допущения есть «Если ошиблись» и дата проверки.
- Риски с высоким влиянием по руту заведены, у них есть план Б.
- Необратимые вопросы (ключи, миграции, деньги, внешние контракты, персональные данные) закрыты решениями, а не допущениями.

## 3. Результат

| Результат | Когда |
|---|---|
| Принят | Всё выполнено |
| Принят с условиями | Можно начинать декомпозиты, но с ограничениями: порядок, зависимость от PM-00, не выключать старый процесс, пока открыто допущение |
| Возвращён | Нет фактов по ключевым разделам, нарезка не от боли, общее спрятано в рут, необратимое на допущении |

## 4. Записать

Ветка, MR и номера — по режиму из `team.md`: таблица «Режим работы» в `AGENTS.md`. В «соло» статус рута меняешь сам после подтверждения человека.


1. Раздел «Приёмка рута» в файле шага — по строке: `python3 tools/kb.py append PM-XX "Приёмка рута" "Архитектор недели: <имя>, <дата>, результат: <…>"`, затем каждое условие: `… append PM-XX "Приёмка рута" "- <условие с ID>"`.
2. Статус рута меняет владелец: «Декомпозиты в работе» при приёмке, «Нарезка» или «Разбор» при возврате. Скажи владельцу.
3. Нашёл проблему, которая касается других рутов или ядра — вопрос через `kb-ask` или решение через `kb-decide`.
4. `python3 tools/kb.py check`. Коммит: `PM-04: приёмка рута — принят с условиями (D-001, A-001)`. MR, ревьюер — владелец рута.

## 5. Скажи человеку

Результат, условия по пунктам, какие декомпозиты можно брать первыми, что вызвало сомнения.
