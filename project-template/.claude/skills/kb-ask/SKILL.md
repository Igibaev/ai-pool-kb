# Задать вопрос

Вопрос в чат не задают: ответ в чате теряется. Вопрос — это файл в `journal/questions/`.

## 1. Подготовка

1. `git pull --rebase`, если есть remote.
2. Сформулируй вопрос одной фразой. Составной — не больше 2–3 подвопросов, иначе разбей на отдельные вопросы. Определи:
   - **тип** и кто ответит — по таблице «Тип вопроса → кто отвечает → канал» в `AGENTS.md`;
   - **раздел**: к какому руту `PM-XX`, системе `SYS-XX` или `ROOT` относится;
   - **блокирует**: какие декомпозиты `PM-XX-NN` не могут двигаться без ответа (может быть пусто).
   Тип «решение» и выбор может сделать пул (ключи, модель, разрез на модули) — не спрашивай, а предложи решение скиллом `kb-decide`.

## 2. Может быть, ответ уже есть

1. Придумай 2–3 формулировки вопроса другими словами: синонимы, термины бизнеса и систем.
2. `python3 tools/kb.py similar "<формулировка 1>" "<формулировка 2>" …` — кандидаты среди вопросов, допущений, решений, рисков и строк фактов во всей базе и материалах.
3. Открой кандидатов, которые по смыслу могут отвечать. Совпадение слов — не ответ: решаешь ты, по смыслу.
4. Вопрос о факте, который можно проверить в коде или файле, — проверь в `materials/`.

Нашёл — покажи человеку ответ со ссылкой на файл и раздел. Вопрос не создавай.

## 3. Может быть, такой вопрос уже задан

Пробеги заголовки открытых вопросов в `journal/_index.md` (по строке на вопрос) и кандидатов из `similar`. Открывай файлы только тех, что похожи. Сравнивай смысл: «кто источник правды по сумме долга» и «откуда брать остаток долга» — один вопрос.

Нашёл похожий — покажи его человеку и спроси: «Это тот же вопрос?»
- **Да** — `python3 tools/kb.py append Q-… Подписчики "<имя>"`; свой нюанс — `python3 tools/kb.py append Q-… Уточнения "<имя>: <нюанс>"`. Шапку чужого вопроса не меняй.
- **Нет** — переходи к созданию.

## 4. Создать вопрос

1. Короткое имя только латиницей через дефис: `istochnik-dolga` (`kb.py` сам транслитерирует кириллицу, но имя человека не используй).
2. Одной командой создай и заполни: `python3 tools/kb.py new question <slug> тип=<…> раздел=<PM-XX|SYS-XX|ROOT> блокирует=<…> заголовок="<вопрос одной фразой>" "Контекст=<почему возник и где искали>"`. Появится файл с временным ID `Q-new-<имя>`.
3. Проверь вывод: строки «ОШИБКА» — исправь значение и повтори `kb.py set`.
4. Если вопрос связан с фактом в шаге, которым владеет этот человек, — добавь в факт ссылку на временный ID. Чужой шаг не правь.

Номер не придумывай: постоянный присвоит CI и сам заменит `Q-new-…` во всех файлах.

## 5. Проверка и отправка

Отправка — по таблице «Режим работы» в `AGENTS.md`: отдельный вопрос — прямой коммит в основную ветку; вопрос во время разбора шага — в MR вместе с шагом.

1. `python3 tools/kb.py check`.
2. Коммит: `git commit -m "Q-new-istochnik-dolga: кто источник правды по сумме долга" -m "Скилл: kb-ask" -- journal/questions/Q-new-istochnik-dolga.md`.
3. Конфликт в разделах «Подписчики» или «Уточнения» — оставь обе строки.

## 6. Что будет дальше — скажи человеку

- Пока вопрос открыт, ответ может дать любой член пула.
- Вопросы к бизнесу без ответа больше 4 рабочих часов дежурный по знаниям включит в пакет для бизнеса; на созвон их понесёт аналитик.
- Если ответа нет 1–2 дня и вопрос блокирует работу — можно оформить допущение скиллом `kb-assume`.
