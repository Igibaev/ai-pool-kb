# Созвон с бизнесом

С бизнесом говорит **аналитик**, не каждый разработчик. Разработчики копят пробелы вопросами в журнале (`kb-ask`), аналитик собирает их в один созвон с одной ролью бизнеса — так бизнес отвечает раз в день, а не десять раз. Ответов за бизнес агент не придумывает.

Проверь по `team.md`, что человек — аналитик или тот, через кого идут вопросы к этой роли бизнеса («Кто кому задаёт вопросы в бизнесе»). Нет — скажи, что созвоны ведёт аналитик, а свой пробел человек оформляет вопросом: `/kb-ask`. Исключение — режим В, шаг 1: список готовит владелец рута.

Три режима: **А подготовить**, **Б разобрать итоги**, **В сверка рута**. Человек не сказал какой — спроси.

## Режим А. Подготовить созвон

1. С кем созвон — роль бизнеса из `team.md`. Не сказал — спроси.
2. Собери вопросы к этой роли: `journal/_index.md`, открытые вопросы со статусом `открыт` или `ждёт бизнес`, типы по таблице «Тип вопроса» в `AGENTS.md` (к бизнесу идут «понимание», «бизнес-правило», «факт о системе» через владельца системы). Раздел вопроса → шаг → «Кто отвечает в бизнесе» — так видно, к кому вопрос. Плюс вопросы со статусом `стал допущением` и открытые допущения этой роли (поле `кто проверяет`) — с пометкой «подтвердите A-…».
3. Отсей:
   - ответ есть в материалах или в другом вопросе — скажи владельцу рута, вопрос не бери;
   - дубли — склей по правилам `kb-sync`.
4. Порядок: сначала то, что блокирует (поле `блокирует`), потом по приоритету рута. Не больше 12 вопросов на 30–40 минут. Не влезло — второй созвон.
5. Переведи на язык бизнеса — без скриптов, полей и таблиц. Где вопрос про то, «как вы это делаете», — проси показать на живом случае:

   | Что выясняем | Как спросить |
   |---|---|
   | Как сейчас | «Покажите на последнем реальном случае, как вы это делаете — по шагам, с экрана» |
   | Объём | «Сколько таких в день? А в самый тяжёлый день? Когда он бывает?» |
   | Исключения | «Что делаете, когда … не находится / не сходится? Покажите такой случай» |
   | Правила | «Как решаете, куда это отнести? Где это правило записано?» |
   | Источник правды | «Если в двух местах разные цифры — какой верить? Кто вправе исправить?» |
   | Цена ошибки | «Что будет, если сделать на день позже? Что случается, когда ошибаются?» |
   | Файлы | «Можете прислать пример файла или выгрузки за обычный день?» |

6. План — в `materials/interviews/<дата>-<роль>-plan.md`: вопросы по порядку, у каждого ID вопроса в журнале. Вопросам из плана — статус `ждёт бизнес`: `python3 tools/kb.py set Q-… статус="ждёт бизнес"`.
7. Владельцам рутов, чьи вопросы в плане, — одна строка в чат: «Q-… идёт на созвон с <ролью> завтра в …». Владелец сложного рута может прийти слушателем — по приглашению аналитика, не по умолчанию.

Подсказки аналитику: просить показать, а не рассказать; цифры записывать словами говорящего — «примерно» это оценка; не предлагать решений; записать встречу, если бизнес согласен.

## Режим Б. Разобрать итоги

1. Заметки или расшифровку сохрани в `materials/interviews/<дата>-<роль>.md`. Сверху: кто проводил, роль собеседника, дата, «Обезличено: да». Имена клиентов, номера документов, телефоны замени до сохранения.
2. По каждому вопросу из плана:
   - ответили — `python3 tools/kb.py append Q-… Ответ "<роль>, <дата>, materials/interviews/<файл>, строка N: <суть>. Записан в: ждёт владельца"` и `python3 tools/kb.py set Q-… статус=отвечен`. Факт в шаг **не пиши**: шаг пишет его владелец, он перенесёт ответ через `/kb-answer` — `kb.py whoami` ему это покажет. Ответы по `ROOT` и рутам без владельца переносит аналитик — `whoami` показывает их как «Ответы без хозяина»;
   - «примерно», «наверное» — так и запиши в ответ: владелец поставит статус `оценка`;
   - **частично**: суть отвечена — `отвечен`, остаток новым узким вопросом; суть не отвечена — услышанное в «Уточнения», статус остаётся `ждёт бизнес`;
   - подтвердили допущение — скажи тому, кто его принял: закрытие через `/kb-answer`.
3. Узнали важное, о чём не спрашивали, — не теряй: в заметках отдельным списком «Не по вопросам», с ID шага. Владелец заберёт это как материал через `/kb-explore`.
4. Новые вопросы, если всплыли, — не больше 3–5: `python3 tools/kb.py new question <slug> тип=<тип> раздел=PM-XX заголовок="…"`. Тип — из таблицы «Тип вопроса» в `AGENTS.md`.
5. `python3 tools/kb.py check`. Отправка — по таблице «Режим работы» в `AGENTS.md`: `git commit -m "Созвон с <ролью> <дата>: ответы на Q-…, Q-…" -m "Скилл: kb-interview" -- <файлы>`.

## Режим В. Сверка рута PM-XX

Рут в статусе «Сверка с бизнесом» — бизнес проверяет содержание шага: «так ли вы работаете?».

1. **Список — владелец рута с агентом** (ещё до созвона). `python3 tools/kb.py context PM-XX`. По каждому заполненному разделу шага — 1–3 утверждения на языке бизнеса: «Вы сопоставляете оплаты по номеру договора, без номера — по ПИНФЛ. Так?». Факты со статусом `оценка` и `допущение A-…` — отдельным блоком «подтвердите». Открытые вопросы рута — в конец. Сохрани в `materials/interviews/<дата>-sverka-PM-XX-plan.md`, скажи аналитику. Владелец приходит на созвон слушателем.
2. **Созвон и итоги — аналитик.** Проводит по списку, заметки — `materials/interviews/<дата>-sverka-PM-XX.md` (шапка как в режиме Б). Без этого файла `kb-slice` рут не нарежет.
3. Разбор заметок — как в режиме Б: ответы в вопросы с «Записан в: ждёт владельца», «не так» по факту без вопроса — новый вопрос с разделом PM-XX и ответом сразу. Факты в шаг не пиши: перенесёт владелец через `/kb-answer`, затем нарежет (`/kb-slice`).
4. Отправка — как в режиме Б.

## Скажи человеку

Сколько вопросов отвечено и по каким рутам — владельцам этих рутов одна строка в чат: «ответ на Q-… в журнале, перенесите в шаг». Что осталось без ответа и когда следующий созвон. В режиме В — что рут можно нарезать.
