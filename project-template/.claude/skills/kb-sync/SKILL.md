# Дежурство по базе знаний

Запускается 2 раза в день: утром — дайджест для всех, около 15:00 — пакет вопросов для бизнеса. Результат — один файл `journal/digest/ГГГГ-ММ-ДД.md` и правки статусов.

## 1. Подготовка

1. `git checkout <основная ветка> && git pull --rebase`.
2. Найди, с какого момента синхронизировать: последний файл в `journal/digest/` и коммит, указанный в нём строкой `Синхронизировано до: <хеш>`. Если дайджестов нет — последние 24 часа: `changes --since "<дата и время сутки назад>"`.
3. `python3 tools/kb.py index` и `python3 tools/kb.py check`. Ошибки проверки перенеси в дайджест — их исправляют авторы.

## 2. Ответы в новых коммитах

1. `python3 tools/kb.py changes --since <хеш>` — коммиты, новые объекты журнала и изменённые строки. Файлы целиком открывай, только если строк мало для вывода.
2. Для каждого открытого вопроса из `journal/_index.md` проверь, не отвечает ли на него одно из изменений — по смыслу.
3. Если похоже на ответ — `python3 tools/kb.py set Q-… статус="возможно отвечен"` и `python3 tools/kb.py append Q-… Уточнения "дежурный: возможно, ответ в <файл#раздел>, коммит <хеш>"`. **Сам не закрывай** — закрывает автор, подтвердив, что ответа достаточно.

## 3. Дубли

1. Для каждого нового вопроса: `python3 tools/kb.py similar "<заголовок>" "<другая формулировка>"` и заголовки открытых вопросов из `journal/_index.md`. Сравнивай по смыслу.
2. Дубль: `python3 tools/kb.py set <поздний> статус=дубль`, `python3 tools/kb.py append <поздний> Ответ "Дубль <ранний>"`, `python3 tools/kb.py append <ранний> Подписчики "<автор дубля>"`, `python3 tools/kb.py append <ранний> Уточнения "<автор>: <нюанс>"`.
3. Сомневаешься — не склеивай, вынеси в дайджест как «возможные дубли».

## 4. Противоречия

Противоречие — два факта по-разному описывают одно и то же: как принимается решение, где источник правды, сколько чего. В том числе внутри одного шага: скрипт делает так, а люди руками — иначе, и неизвестно, что из этого правило.
1. Пройди изменённые строки про правила, источники правды и объёмы и сравни их со всеми фактами того же шага.
2. Для каждой такой строки — `python3 tools/kb.py similar "<суть факта>"`: на ту же тему в других файлах может быть записано другое.
3. Нашёл — не выбирай сам, кто прав. Если по теме уже есть открытый вопрос — допиши ссылки в его «Уточнения». Нет — `python3 tools/kb.py new question <slug>` с двумя ссылками: тип «бизнес-правило», если выбирает бизнес, «решение» — если пул. Вынеси в дайджест.

## 5. Сроки

- Пакет для бизнеса — в дневной запуск. Туда — вопросы типов «бизнес-правило», «решение», «скоуп», открытые больше 4 рабочих часов (рабочие часы — поле `рабочие часы` в `team.md`), статус `ждёт бизнес`. Утренний запуск статусы `ждёт бизнес` не ставит.
- Вопросы, открытые больше 2 рабочих дней и блокирующие декомпозиты, — в дайджест с рекомендацией оформить допущение.
- Допущения с прошедшей датой «проверить до» — статус `просрочено`, в дайджест для техлида потока.
- Открытые риски с высоким влиянием — в дайджест каждый день. Если в новых коммитах или ответах бизнеса видно, что сигнал риска сработал, — допиши в «История» риска строку `дежурный: возможно, сработал сигнал — <что увидел>` и вынеси в дайджест для того, кто следит.

## 6. Дайджест

Создай `journal/digest/ГГГГ-ММ-ДД.md` (если файл за сегодня есть — допиши новый раздел со временем):

```markdown
# Дайджест ГГГГ-ММ-ДД, <время>
Синхронизировано до: <хеш HEAD>

## Что изменилось в базе знаний
- PM-04: <что добавили>, <кто>

## Закрыто
- Q-014 отвечен: <суть>, записан в <файл>

## Возможно отвечено — авторам проверить
- Q-021 (<автор>): ответ, похоже, в <файл#раздел>

## Склеены дубли / возможные дубли

## Противоречия — нужно решение

## Пакет для бизнеса
Письмом — короткие вопросы. Где нужен показ или разговор — созвон: `/kb-interview`.
Сгруппировано по темам, без дублей, одной фразой каждый вопрос.
### <тема>
- Q-… <вопрос> — кто ждёт: <подписчики>, блокирует: <…>

## Просрочено
- A-007 проверить до <дата>, кто проверяет: <…>

## Рекомендовано оформить допущение

## Риски с высоким влиянием
- R-003 <риск> — следит: <кто>, сигнал: <…>

## Ошибки проверки
```

## 7. Отправка
Ветка, MR и номера — по режиму из `team.md`: таблица «Режим работы» в `AGENTS.md` (в «команде» — ветка и MR, в «соло» — основная ветка и `after-merge`).


1. `python3 tools/kb.py index` и `python3 tools/kb.py check` ещё раз.
2. Коммит: `kb-sync: дайджест ГГГГ-ММ-ДД`.
3. `git pull --rebase`, push. Если основная ветка защищена — MR с автослиянием.

## 8. Скажи человеку

Кратко: сколько закрыто, сколько ждёт бизнес, что просрочено, есть ли противоречия. Пакет для бизнеса аналитик просматривает и отправляет сам — агент бизнесу не пишет.
