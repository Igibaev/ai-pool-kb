# Шаблон проекта

**Людям — начинать с [`docs/README.md`](docs/README.md).** Файлы заполняет агент через скиллы, руками шаблоны не заполняют.

Универсальная структура для любого продукта, который делает пул с ИИ-агентами.
Копируется в новый репозиторий как есть. Продуктовое содержание появляется по ходу работы.

## Что где лежит

```
product.md               Рутовый эпик: цель, боль, метрика, критерии приёмки
materials/               Сырые материалы бизнеса: скрипты, файлы, регламенты, интервью
context/                 Знание о процессе бизнеса — «как есть сейчас»
  glossary.md            Единый язык: термины и их значения
  process/               Карта процессов: один файл на шаг = один рут
    _index.md            Сводка по рутам (генерируется)
  systems/               Карта систем: один файл на внешнюю систему
core/                    Ядро проекта: общее для всех рутов
  domain-model.md        Сущности, жизненный цикл главного объекта, источники правды
  context-map.md         Модули и сервисы, владение данными, события между ними
  conventions.md         Сквозные соглашения: ID, деньги, время, ошибки, тоглы
journal/                 Журналы
  _index.md              Сводка открытых вопросов и допущений (генерируется)
  _renames.tsv           Какие временные ID стали какими номерами (пишет CI)
  questions/             Вопросы: чего мы не знаем
  assumptions/           Допущения: не знаем, но временно решили сами
  decisions/             Решения: решили окончательно
  risks/                 Риски: что может пойти не так и что делаем
  digest/                Ежедневный дайджест дежурного по знаниям
specs/                   Спеки декомпозитов, по ним агент пишет код
datasets/                Золотой датасет: реальные случаи с ожидаемым результатом
services/                Код
tools/kb.py              Проверка, сводки, нумерация журнала, поиск ссылок
team.md                  Кто есть кто: имена как в git, роли, режим «команда» или «соло», архитектор недели, дежурный по знаниям, контакты бизнеса
docs/                    Инструкции для людей: установка, скиллы, карта процессов, шаблоны, направления мысли, прогон
AGENTS.md                Правила для агента — общие для Claude Code и OpenCode
CLAUDE.md                Подключает AGENTS.md для Claude Code
FEEDBACK.md              Замечания к самим скиллам и правилам во время пилота
.claude/skills/          Скиллы агентов: Claude Code и OpenCode читают их отсюда, вызов — /<имя>
.opencode/commands/      Команды /kb-… для OpenCode: вставляют скилл в сообщение
.opencode/agents/kb.md   Агент OpenCode для своей модели: жёсткие правила, низкая температура
opencode.json            Настройки OpenCode: агент kb по умолчанию, разрешения, сжатие контекста
.gitlab-ci.yml           Проверка на MR, номера и сводки после каждого коммита в основную ветку
```

## Иерархия работы

| Уровень | Где живёт | Статусы |
|---|---|---|
| Рутовый эпик | `product.md` | — |
| Рут = шаг карты процессов | `context/process/PM-XX-*.md` | Черновик → Готов к взятию → Разбор → Сверка с бизнесом → Нарезка → Приёмка → Декомпозиты в работе → Готово. Кто ставит каждый — `AGENTS.md`, «Статусы рута». Руты не назначают — разработчики берут сами: `kb.py take` |
| Декомпозит | `specs/PM-XX/PM-XX-NN-*/` | Опции → Спека → Ревью спеки → Сборка → Приёмка → Канарейка → Готово |
| Задача агента | `plan.md` внутри декомпозита | На доску не выносится |

Общие части, нужные нескольким рутам, живут в отдельном руте `PM-00 Каркас и общие части`, его содержание — папка `core/`. Ведёт техлид потока (нет — архитектор недели).

## Идентификаторы

| Объект | Формат | Пример |
|---|---|---|
| Рут (шаг процесса) | `PM-XX` | `PM-04` |
| Декомпозит | `PM-XX-NN` | `PM-04-02` |
| Система | `SYS-XX` | `SYS-01` |
| Вопрос | `Q-NNN` | `Q-014` |
| Допущение | `A-NNN` | `A-007` |
| Решение | `D-NNN` | `D-005` |
| Риск | `R-NNN` | `R-003` |
| Случай датасета | `GD-PM-XX-NNN` | `GD-PM-04-017` |

ID никогда не переиспользуется. Ссылки между файлами — только по ID.
Вопросы, допущения, решения и риски создаются с временным ID `Q-new-<имя>`, постоянный номер присваивает CI после каждого коммита в основную ветку (см. `tools/README.md`).

## Три правила, на которых держится всё остальное

1. У каждого факта есть источник и статус: `(источник, подтверждено | оценка | допущение A-NNN | противоречие)`.
2. Ответ существует, только если он записан коммитом. Коммит с ответом содержит ID вопроса или допущения.
3. Один файл — один писатель. Файлы создаёт `kb.py new …` по шаблонам `_template`; структуру меняет аналитик, содержание — весь пул. Кто что пишет, что идёт через MR, а что прямым коммитом, — `AGENTS.md`.
