# Сквозные соглашения

Соглашения, которые одинаковы для всех рутов и сервисов. Агент читает этот файл перед каждой задачей.
Значения в угловых скобках заполняют техлиды потока при старте продукта.

## Идентификаторы
- Ключ сущности генерирует система-владелец: <UUID / ULID / последовательность>.
- Внешние номера хранятся как отдельные поля с указанием системы и даты появления. Внешний номер никогда не становится ключом.

## Деньги
- Сумма хранится в минимальных единицах валюты целым числом: <да/нет, тип>.
- Каждая сумма хранится вместе с валютой. Курс — на дату операции, вместе с источником курса.
- Округление: <правило>. Остаток от округления: <куда уходит>.
- Денежная операция идемпотентна: повторный вызов с тем же ключом не создаёт вторую операцию.

## Время
- Хранение в <UTC>. Отображение в часовом поясе <пользователя / страны>.
- Бизнес-даты (дата платежа, дата документа) хранятся как даты без времени.
- «Конец дня» для правил: <часовой пояс>.

## Ошибки и валидация
- Формат ошибки API: <код, сообщение, поле>.
- Ошибка внешней системы не роняет процесс: запись уходит в очередь повторной обработки и видна человеку.

## Логирование и наблюдаемость
- Каждая запись лога содержит модуль, ID главного объекта, ID запроса.
- Метрики помечены модулем, чтобы проблемы были видны по модулям.

## Тоглы и выкатка
- Тогл обязателен для рискованного: деньги и расчёты, интеграции, замена работающего процесса, решения на допущениях.
- Остальное — по решению владельца, записанному в спеке.
- Тогл имеет владельца и срок снятия. Снятие тогла — отдельная задача.

## Миграции данных
- Миграция — необратимая точка: код миграции смотрит человек.
- Сначала прогон на копии, отчёт расхождений, потом бой.

## Необратимые точки
Человек смотрит код только здесь:
- миграции данных;
- денежные операции;
- внешние контракты и интеграции;
- безопасность и персональные данные.
Такие места помечаются в спеке заранее.
