# С чего начать

Этот репозиторий — общая память пула о продукте: что делает бизнес, чего мы не знаем, что решили, что строим. Его заполняют агенты по скиллам. Человек говорит агенту, что произошло, приносит материалы и проверяет результат.

## Три правила

1. **Факт — только с источником.** `Скрипт ищет надпись по номеру (materials/scripts/match_payments.py, подтверждено)`. То, что «обычно так бывает», — вопрос, а не факт.
2. **Ответ существует, только если он записан коммитом.** Ответ в чате потерян. Вопрос в чате потерян.
3. **У каждого файла один писатель.** Шаг процесса пишет владелец рута, карту — аналитик, ядро — техлид потока. Остальные приносят правки через MR или вопрос. Кто что пишет и что идёт прямым коммитом — `AGENTS.md`.

## Как выглядит день

| Время | Что | Кто | Скилл |
|---|---|---|---|
| 09:00 | Дайджест: что изменилось, что закрыто, дубли, противоречия | Дежурный по знаниям недели | `kb-sync` |
| День | Разбор шагов, вопросы, допущения, ответы | Все | `kb-explore`, `kb-ask`, `kb-assume`, `kb-answer` |
| 15:00 | Пакет вопросов для бизнеса | Дежурный по знаниям недели | `kb-sync` |
| Вечер | Ответы бизнеса — в базу; сверка рутов с бизнесом | Аналитик, владельцы | `kb-interview`, `kb-answer` |

## Перед первой сессией

Установка и настройка — [setup.md](setup.md). Коротко:
1. `git config user.name "Имя"` — так же, как вас записывают в `team.md`. Агент сверяет это имя с владельцами файлов.
2. Откройте папку репозитория в Claude desktop (вкладка Code) или запустите Claude Code / OpenCode из корня.
3. Наберите `/kb-next` — агент скажет, что у вас в работе и что делать дальше.

Пилот на своём продукте по шагам — [test-run.md](test-run.md). Замечания к скиллам — в `FEEDBACK.md` в корне.
