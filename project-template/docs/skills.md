# Как работать со скиллами

## Что такое скилл

Скилл — инструкция для агента: как сделать одну работу по правилам пула. Например, «задать вопрос без дублей» или «оформить допущение с ценой ошибки». Скиллы лежат в `.claude/skills/`. Их читают и Claude Code (в том числе вкладка Code в Claude desktop), и OpenCode.

Человеку не нужно помнить шаблоны и правила. Нужно:
1. сказать агенту, что произошло или что нужно;
2. дать материалы;
3. ответить на его вопросы;
4. проверить результат перед MR.

**Шаблоны руками не заполняют.** Файлы журнала, шагов, систем создаёт агент. Вы читаете шаблоны в [templates.md](templates.md), чтобы понимать, что получится.

## Как запустить

Три способа, результат одинаковый:

| Способ | Пример | Когда удобно |
|---|---|---|
| Команда | `/kb-explore PM-04, разбираю скрипт сопоставления` — в Claude Code любой скилл вызывается как `/<имя>` | Знаете, какой скилл нужен |
| Своими словами | «Разбери шаг PM-04 по скрипту match_payments.py, я владелец» | Не помните название — агент выберет сам |
| Подсказка | `/kb-next` | Не знаете, что делать дальше |

Если агент выбрал не тот скилл — скажите прямо: «используй kb-ask».

## Что сказать агенту

| Ситуация | Что сказать | Скилл | Что получится |
|---|---|---|---|
| Создали репозиторий, есть запрос бизнеса и файлы | «Вот запрос бизнеса и материалы, заполни карточку продукта» | `kb-init` | `product.md`, материалы по папкам |
| Нужна карта процессов | «Построй черновик карты процессов по материалам» | `kb-map` | `_map.md`, файлы шагов, систем, глоссарий, список вопросов на сверку |
| Бизнес поправил структуру | «Бизнес говорит, что МИБ и приставы — разные шаги» | `kb-map` | Изменённая карта, строка в «Изменения структуры» |
| Шаги на карте, пора отдавать в работу | «Подготовь шаги к взятию» | `kb-map` | Материалы и контакты, приоритет, статус «Готов к взятию» |
| Освободились, хотите рут | «Что можно взять?» или `/kb-take PM-04` | `kb-take` | Вы владелец рута, статус «Разбор», коммит в основную ветку |
| Взяли рут | «Разбери PM-04, вот скрипт и выгрузка» | `kb-explore` | Заполненные разделы шага, вопросы по пробелам |
| Разбираете чужой рут | «Я тестировщик, разбери выписку для PM-04» | `kb-explore` | MR владельцу рута, случаи в `datasets/` |
| Аналитик: пора созвониться с бизнесом | «Подготовь созвон с бухгалтером» | `kb-interview` | План из вопросов пула к этой роли, языком бизнеса |
| Аналитик: созвон прошёл | «Вот заметки после звонка с бухгалтером» | `kb-interview` | Заметки в `materials/interviews/`, ответы в вопросах |
| Владелец: ответ ждёт переноса | «Перенеси ответ Q-007 в шаг» | `kb-answer` | Факт в шаге с источником |
| Чего-то не знаете | «Не понимаю, кто источник правды по долгу» | `kb-ask` | Ответ из базы, подписка на похожий вопрос или новый вопрос |
| Бизнес молчит 2 дня | «По Q-002 ответа нет, предлагаю считать 1С МФО» | `kb-assume` | Допущение с ценой ошибки и датой проверки |
| Пришёл ответ | «Главбух ответила письмом: остаток только в 1С МФО» | `kb-answer` | Факт в шаге, закрытый вопрос, подтверждённое допущение, список мест |
| Надо выбрать вариант | «Нужен ключ надписи: номер договора, номер нотариуса или свой» | `kb-decide` | Решение с вариантами и последствиями |
| Тревожит что-то | «Боюсь, 1С МФО не примет 100 тыс. надписей» | `kb-risk` | Риск с сигналом и планом Б |
| Шаг сверен с бизнесом | «Нарежь PM-04» | `kb-slice` | Таблица декомпозитов, вопросы в PM-00 |
| Архитектор недели принимает рут | «Прими PM-04» | `kb-accept` | Отчёт по проверке, раздел «Приёмка рута» |
| Утро или 15:00 у аналитика | «Дежурство» | `kb-sync` | Дайджест, склеенные дубли, пакет для бизнеса |
| Руководитель: конец недели, ретро | «Кто что делал за неделю? Где буксует процесс?» | `kb-activity` | Действия людей по git, сроки рутов, сигналы, до 5 предложений по процессу и скиллам |

## Путь одного рута по скиллам

```
kb-map            аналитик создаёт шаг в карте            статус: Черновик
kb-map режим 3    аналитик готовит к взятию               статус: Готов к взятию
   ↓
kb-take           разработчик берёт сам                   статус: Разбор
kb-explore        владелец и пул разбирают материалы
kb-ask            чего нет в материалах → вопрос бизнесу
kb-interview      аналитик: вопросы пула → созвон → ответы
kb-ask            пробелы → вопросы
kb-sync           дубли, противоречия, пакет для бизнеса
kb-answer         ответы бизнеса → факты
kb-assume         долго нет ответа → допущение
   ↓
встреча с бизнесом «так вы работаете?»                    статус: Сверка с бизнесом
kb-answer         итоги встречи → факты
   ↓
kb-slice          нарезка на декомпозиты                  статус: Нарезка → Приёмка
kb-decide         общее для нескольких рутов → PM-00
   ↓
kb-accept         архитектор недели принимает             статус: Декомпозиты в работе
```

Живой пример этого пути за неделю — в симуляции `vzyskanie-repo-simulyaciya`.

## Что агент спросит у вас

Хороший агент по скиллу задаёт вопросы, а не угадывает. Ожидайте:
- «Вы владелец этого рута?» — если имя в git не совпадает с владельцем.
- «Какие материалы разбираем?» — если вы не дали файлы.
- «Это тот же вопрос, что Q-002?» — если нашёл похожий.
- «Кто примет допущение?» — если оно затрагивает несколько рутов.
- «В материале нет ответа, завести вопрос?»

Отвечайте коротко. Не знаете — так и скажите: агент заведёт вопрос.

## Что проверить перед MR

Агент делает работу, вы за неё отвечаете. Две минуты на проверку:

1. **Факты с источником.** Откройте 2–3 источника: там правда так написано?
2. **Ничего не придумано.** Нет фраз «обычно», «как правило», «скорее всего» в фактах.
3. **Чужое не тронуто.** В изменённых файлах только ваши: `git status`.
4. **Вопросы понятны бизнесу.** Без названий скриптов и полей базы, одной фразой.
5. **Проверка зелёная.** `python3 tools/kb.py check` — ошибок 0.
6. **Коммит маленький.** Один раздел или один объект журнала, ID в сообщении.

## Частые ошибки

| Ошибка | Что будет | Как правильно |
|---|---|---|
| Задать вопрос в чате пула | Ответ потеряется, вопрос зададут ещё трижды | «Задай вопрос» агенту — `kb-ask` |
| Записать ответ бизнеса только в чат | Через неделю никто не вспомнит | Ответ → агенту → `kb-answer` |
| Править чужой шаг напрямую | Конфликт, владелец не узнает | Агент сам сделает MR владельцу |
| Писать в шаг, как должно быть | Спеки строятся на фантазии | Шаг — как есть сейчас. Как должно — в спеке |
| Придумать номер Q-015 | Два человека займут один номер | Номер присвоит CI |
| Не настроить `git config user.name` | Агент не поймёт, что вы владелец | Настроить один раз |
| Держать ветку неделю | Конфликты со всеми | Ветка живёт часы |

## Если не хватает опыта анализа

Это нормально, особенно на первом руте. Пробелы не закрывают догадками — агент и пул помогают их закрыть.

| Что происходит | Что делать |
|---|---|
| Не понимаете, что писать в разделе | Спросите агента в `kb-explore`: «что здесь нужно и где это искать?» — он объяснит по `thinking.md` и покажет пример из `templates.md` |
| В материалах ответа нет | Вопрос через `/kb-ask` языком бизнеса. Аналитик понесёт его на созвон, ответ придёт в вопрос — перенесёте через `/kb-answer` |
| Не уверены, факт это или догадка | Пусть будет вопрос. Цифра со слов «примерно» — `оценка`, это нормально |
| Первый рут | Аналитик — ревьюер вашего MR |
| После созвона ключевые разделы всё ещё пусты | Позовите аналитика в пару. Рут остаётся вашим |
| Понимаете, что рут не ваш (не та система, срочная работа) | `/kb-take` → «верни рут», с причиной. Всё, что успели, остаётся |

## Для руководителя: настройка процесса и инструмента

Процесс и сами скиллы — не застывшие. Руководитель раз в неделю смотрит `/kb-activity`:

- **кто что делал** — взятые руты, факты, вопросы, ответы, допущения, решения, датасеты — по истории git всех веток;
- **руты** — сколько дней в статусе и без правок;
- **вопросы к бизнесу** — сколько ждут и как быстро отвечают;
- **сигналы** — рут долго не берут, рут в разборе без правок, вопросы висят, один человек стал узким местом, агенты нарушают правила;
- **`FEEDBACK.md`** — что люди пишут про скиллы.

Числа — не оценка людей: сложный разбор даёт мало коммитов, менеджер и архитектор работают не только в git. Отчёт показывает, где менять процесс. Почему у человека нет правок, видно только из разговора с ним.

Правки скиллов и правил руководитель делает в репозитории шаблона веткой и MR — так изменения инструмента видны так же, как изменения продукта. Какие скиллы реально используют, видно по строке `Скилл: kb-…` в коммитах (правило 6 `AGENTS.md`).

Команда без агента: `python3 tools/kb.py activity --since 7д`, страница — `--html reports/activity.html`.

## Как думать

Скилл говорит агенту, **как** оформить. **Что** искать в материалах — направления мысли в [thinking.md](thinking.md). Агент проходит по ним сам, но лучшие вопросы рождаются у человека, который их знает.
