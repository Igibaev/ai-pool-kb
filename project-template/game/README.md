# Игра: неделя пула за один день

Тестовый прогон процесса на выдуманном продукте. Команда проходит путь от пустого репозитория до принятого рута — карта, разбор, вопросы, созвоны с бизнесом, нарезка, приёмка, отчёт руководителя. Спеки и код в игру не входят.

Два набора материалов:

| Набор | Продукт | Чем похож на нашу работу | Папка |
|---|---|---|---|
| 1 | «Сарыарка Су» — досудебное взыскание долгов за воду | Та же природа, что взыскание: стадии, уведомления, пеня, юристы, ЧСИ; есть скрипт, регламент, выгрузка | `1-kommunalka/` |
| 2 | «ТехноСервис» — заявки на ремонт бытовой техники и акты производителю | Другая предметная область; меньше материалов, больше нужно спрашивать у бизнеса | `2-servis-centr/` |

В каждой папке:
- `inbox/` — то, что игроки получают в начале. Это всё, что «прислал бизнес».
- `vedushchiy/` — только для ведущего: ответы бизнеса по ролям, ожидаемая карта, что не знает никто, заложенные ловушки. Игрокам не показывать.

Один набор — один день. Если играете оба, второй — другим составом ролей, чтобы аналитик побыл разработчиком.

## Роли

| Роль | Кто | Что делает в игре |
|---|---|---|
| Ведущий = бизнес | 1 человек, не из пула | Отвечает за все роли бизнеса по `vedushchiy/otvety-biznesa.md`. Только на созвонах с аналитиком, только на спрошенное. Ведёт лист наблюдений |
| Аналитик | 1 | `kb-init`, `kb-map`, созвоны и сверки (`kb-interview`), дежурство (`kb-sync`) |
| Разработчики | 2–4 | `kb-take`, `kb-explore`, `kb-ask`, `kb-answer`, `kb-slice` |
| Тестировщик | 1 | Напарник в руте на двоих: объёмы, исключения, датасет |
| Архитектор недели | 1 из разработчиков | `kb-accept`, согласование допущений, решения |
| Техлид потока | 1 из разработчиков | PM-00, `kb-decide` |
| Руководитель | 1 | `kb-activity` в конце дня. Может совмещать с ведущим, если людей мало |
| Менеджер | по желанию | Приоритеты шагов вместе с аналитиком |

Минимальный состав — 4 человека: ведущий, аналитик, два разработчика (один из них архитектор, второй техлид). Тогда созвонов меньше, а руты на двоих не будет.

## Подготовка (ведущий, 30 минут накануне)

1. Репозиторий продукта из `project-template/`: `cp -r project-template ~/igra-1 && cd ~/igra-1 && git init -b main && git add -A && git commit -m "Шаблон"`.
2. Общий remote. Без GitLab: `git init --bare /shared/igra-1.git` на общем диске или на одном ноутбуке, у всех `git remote add origin …`. С GitLab — настройки из `docs/setup.md` (push в main для Developers). Без CI номера раздаёт дежурный: после каждого слияния `python3 tools/kb.py after-merge` и коммит «kb: номера и сводки».
3. У каждого игрока: клон, `git config user.name "Имя"` ровно как будет в `team.md`, Claude desktop или OpenCode, открыта папка репозитория. Проверка: `/kb-next` отвечает.
4. Скопировать `game/<набор>/inbox/*` в `inbox/` репозитория аналитика. Не коммитить — это сделает `kb-init`.
5. Распечатать или открыть у себя `vedushchiy/otvety-biznesa.md` и лист наблюдений (ниже).
6. Договориться о часах созвонов с бизнесом. Бизнес доступен **два раза в день** по 30 минут и один раз отвечает письмом. Между созвонами на вопросы не отвечает — это и проверяем.

## Расписание

| Время | Что | Кто | Скилл | Ведущий смотрит |
|---|---|---|---|---|
| 9:00 | Старт: team.md, материалы, карточка продукта | Аналитик | `kb-init` | Поймал ли агент персональные данные (набор 2, строка 10 CSV); не придумал ли метрику |
| 9:40 | Черновик карты | Аналитик | `kb-map` | Главный объект; шаги по переходам состояния, а не по отделам |
| 10:15 | Сверка структуры с бизнесом, 20 минут | Аналитик + ведущий | — | Ведущий отвечает только про структуру |
| 10:40 | Правки карты, подготовка шагов к взятию: материалы, контакты, приоритет, людей | Аналитик (+ менеджер) | `kb-map` режим 2 и 3 | Аналитик не пишет «Как сейчас»; подсказка «людей» принята осознанно |
| 11:00 | Взятие рутов | Разработчики, техлид — PM-00 | `kb-take` | Берут сверху по приоритету; напарник в руте на двоих; третьему отказ |
| 11:10–13:00 | Разбор рутов, вопросы | Разработчики, тестировщик | `kb-explore`, `kb-ask` | Факты с источниками и строками; пробелы — вопросами, не догадками; MR на свой шаг |
| 13:00 | Дежурство: дубли, противоречия, пакет вопросов | Аналитик (дежурный) | `kb-sync` | Нашёл ли заложенные противоречия; склеены ли дубли |
| 13:30 | Созвон 1 с бизнесом, 30 минут | Аналитик + ведущий | `kb-interview` А, потом Б | Вопросы языком бизнеса, не больше 12; ответы — в вопросы, не в чужие шаги |
| 14:00 | Перенос ответов в шаги, продолжение разбора; рут готов — «Сверка с бизнесом» | Владельцы | `kb-answer`, `kb-explore` | `whoami` показал ожидающие ответы; статус ставит владелец |
| 15:00 | Допущение по вопросу, на который бизнес не ответил | Один из владельцев, архитектор согласует | `kb-assume` | Цена ошибки и дата проверки; согласование строкой в «Почему» |
| 15:30 | Созвон 2: сверка одного рута с бизнесом | Аналитик ведёт, владелец слушает | `kb-interview` В | Файл сверки появился; владелец переносит итоги сам |
| 16:00 | Нарезка сверенного рута; вопрос «скоуп» в PM-00; решение техлида | Владелец, техлид | `kb-slice`, `kb-decide` | kb-slice отказал без файла сверки; общее ушло в PM-00 |
| 16:40 | Приёмка | Архитектор недели | `kb-accept` | Проверил факты по источникам; «Декомпозиты в работе» только без блокеров; самоприёмка названа |
| 17:00 | Отчёт по дню | Руководитель | `kb-activity` | Сигналы совпали с тем, что видел ведущий |
| 17:20 | Разбор: что мешало, FEEDBACK.md | Все | — | Каждый записывает хотя бы одно наблюдение |

Если отстаёте — режьте созвон 2 до 15 минут и нарезку одного рута, но до приёмки дойдите: без неё не проверить статусную машину.

## Правила игры

1. Бизнес отвечает только через аналитика на созвонах. Разработчик, который «просто спросил ведущего в коридоре», получает ответ «я вас не слышу».
2. Нельзя смотреть в `vedushchiy/`.
3. Всё, что сказано на созвоне и не записано коммитом, бизнес через час «забывает». Ведущий имеет право на следующем созвоне ответить иначе на вопрос, которого нет в журнале.
4. Факт без источника — ведущий в конце дня ищет такие в шагах и показывает команде. Это главная проверка.
5. Агент, а не человек, правит файлы. Руками — только когда скилл говорит «правь точечно».

## Что считать успехом

- Карта: главный объект назван верно (см. `vedushchiy/`), шаги по переходам состояния, структура сверена с бизнесом — строки в «Изменения структуры».
- Хотя бы два рута дошли до «Сверка с бизнесом», один — до «Декомпозиты в работе» или «Приёмка с условиями».
- В шагах нет ни одного факта из списка «чего не знает никто» со статусом «подтверждено».
- Заложенные противоречия найдены и оформлены: оба факта с источниками, статус `противоречие`, вопрос правильного типа.
- Персональные данные в репозиторий не попали (набор 2).
- В журнале нет дублей, у каждого отвеченного вопроса есть «Записан в».
- `kb-activity` в конце дня показал то же, что видел ведущий.
- В `FEEDBACK.md` — не меньше 10 записей. Это главный результат игры: что в скиллах мешало.

## Лист наблюдений ведущего

Одна строка на наблюдение, в любой момент дня:

| Время | Кто | Скилл | Что произошло | Серьёзность (ломает / мешает / неудобно / идея) |
|---|---|---|---|---|

Отдельно отмечайте:
- сколько раз агент спросил человека то, что уже было в файлах;
- сколько раз человек правил файл руками в обход команд;
- где агент предложил выдумать («скорее всего…») и остановил ли его человек;
- сколько времени ушло на `kb-init` и на карту — это нагрузка аналитика;
- что люди делали, пока ждали бизнес.

После игры: лист наблюдений и `FEEDBACK.md` — в репозиторий инструмента как задачи, самое больное — в скиллы на следующей неделе. Отчёт `python3 tools/kb.py report` — архив для разбора.

## Второй день (если есть)

Набор 2 тем же составом, но роли сдвинуты: вчерашний аналитик — разработчик, вчерашний разработчик — аналитик. Цель второго дня — проверить, что процесс не держится на одном человеке, который его придумал.
