# Инструменты

`kb.py` — проверка и обслуживание базы знаний и журнала. Только стандартная библиотека Python 3.9+.

| Команда | Что делает | Кто запускает |
|---|---|---|
| `python3 tools/kb.py check` | Проверяет шапки, формат ID, уникальность, статусы, ссылки на несуществующие объекты, просроченные допущения | Агент перед коммитом; CI на каждом MR |
| `python3 tools/kb.py index` | Пересобирает `context/process/_index.md` и `journal/_index.md` | CI после слияния; дежурный по знаниям |
| `python3 tools/kb.py new question <имя>` | Создаёт вопрос с временным ID `Q-new-<имя>` | Агент |
| `python3 tools/kb.py new assumption <имя>` | Создаёт допущение `A-new-<имя>` | Агент |
| `python3 tools/kb.py new decision <имя>` | Создаёт решение `D-new-<имя>` | Агент |
| `python3 tools/kb.py new risk <имя>` | Создаёт риск `R-new-<имя>` | Агент |
| `python3 tools/kb.py assign-ids` | Присваивает постоянные номера временным ID и заменяет их во всех файлах | Только CI, только в основной ветке |
| `python3 tools/kb.py context <PM-XX\|SYS-XX>` | Всё о шаге одной выжимкой: кто работает и владелец ли он, место на карте, файл шага, журнал по руту, глоссарий, нарезка других рутов | Агент вместо чтения пяти-семи файлов |
| `python3 tools/kb.py similar "<текст>" ["<синонимы>"]` | Кандидаты среди вопросов, допущений, решений, рисков и строк фактов — по словам | Агент перед новым вопросом и при поиске дублей |
| `python3 tools/kb.py changes --since <хеш>` | Коммиты, новые объекты журнала, изменённые строки | Дежурный |
| `python3 tools/kb.py peek <файл>` | Паспорт большого файла: колонки, частые значения, первые строки с номерами | Агент перед разбором выгрузки |
| `python3 tools/kb.py map` | Рисует карту процессов: `_map.svg` и интерактивную `_map.html` со статусами, владельцами, вопросами и декомпозитами. Вызывается и из `index` | Аналитик после правки карты; CI |
| `python3 tools/kb.py after-merge` | assign-ids и index — то, что делает CI | Соло-режим |
| `python3 tools/kb.py report` | Архив для разбора: база знаний, FEEDBACK.md, история | Пилот |
| `python3 tools/kb.py refs <ID>` | Находит все упоминания ID: контекст, спеки, тесты, код | Агент, когда меняется допущение или решение |

## Что настроить в CI

**На каждом merge request:**
```
python3 tools/kb.py check
```
MR не сливается, если есть ошибки.

**После слияния в основную ветку** (задачи этого шага должны выполняться строго по одной, без параллельных запусков):
```
python3 tools/kb.py assign-ids
python3 tools/kb.py index
git add -A && git commit -m "kb: номера и сводки [skip ci]" && git push
```

Почему номера присваивает CI, а не человек: двое, создавших вопрос одновременно, иначе получат одинаковый номер. Последовательный запуск в основной ветке гарантирует, что номер уникален.
