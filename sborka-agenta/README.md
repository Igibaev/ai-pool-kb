# Сборка агента — кухня

Здесь только то, что нужно для сборки: порции, решения, покрытие требований. В репозиторий продукта эта папка не переносится.

Сам агент — папка `agent/`. Он универсальный: ядро одинаково во всех проектах, всё о продукте — в файлах проекта. Папка устроена как корень ветки базы любого продукта; первый — `debt-enforcement-service`. Перенос — скопировать содержимое `agent/` в корень ветки базы и заполнить файлы проекта.

```
agent/                             → корень ветки context
  AGENTS.md                        короткое ядро: 12 правил, ворота, как говорить, где что лежит
  .gitignore                       .kb/ — личное, в git не попадает
  kb/
    product.md                     продукт: для кого, главный объект, границы, MVP (шаблон, проект)
    team.md                        команда и роли (шаблон, проект)
    project.md                     ветки базы и кода, закрытые пути (проект)
    ai.json                        модели по уровням Л / С / Т, без ключей (проект)
    rules/
      flow.md                      8 этапов флоу, статусы, кто решает — по нему работает штурман
      gates.md                     ворота: жёсткие / с причиной / подсказки; где можно обойти
      formats.md                   форматы факта, шага, вопроса, решения, находок, пакета
      models.md                    какая модель на какой шаг
      roles/<роль>.md              чем агент помогает роли на каждом этапе (7 ролей)
    context/process/notes/         находки не-владельца шага
    context/systems/
    journal/questions/ views/ packages/ reports/ assumptions/ decisions/ risks/
    materials/ inbox/ datasets/ delivery/
    docs/zapusk.md                 первый запуск для команды: установка, модели, OpenCode
    tools/
      README.md
      kb.py, kb*.py                инструмент `kb`: только stdlib, Python 3.9+
      hooks/pre-commit             то, что нельзя коммитить никому
      code-kit/                    набор для папки кода: мост kbx.py, CI против kb/, правила агента кода
      eval/                        стенд проверки агента на живой модели: сценарии E1–E8
      tests/oshibki.md             что инструмент обязан отклонить — у каждой строки свой тест
      tests/fixture/               маленькая база в новом формате — данные для тестов
sborka-agenta/                     эта папка

  pokrytie.md                      требования → чем закрыты → какой тест
```

Структура — по документу владельца «Структура проекта», раздел 3. Отличия — в `resheniya.md`, раздел «Отличия от предложенной структуры».

## Как проверить порцию 6 — запуск агента

Это первый полный запуск на ваших моделях. 30 минут.

**1. Тестовая база** — как в порции 3, плюс агент целиком:
```bash
R=$(mktemp -d) && cp -R agent/. $R/ && rm -rf $R/kb/context $R/kb/journal $R/kb/materials \
  && cp -R agent/kb/tools/tests/fixture/. $R/kb/ && cd $R
git init -q && git config user.name "Разработчик-1" && git config user.email dev1@example.local
git add -A && git commit -qm старт && python3 kb/tools/kb.py hooks
```

**2. Модели** — `kb/rules/models.md`, раздел «Как задать модели». Проверка: `python3 kb/tools/kb.py models`.

**3. OpenCode** (через kalude) в папке `$R`. Auto mode не включать.

| Что ввести | Что должно быть |
|---|---|
| `/gde` | Три строки: PM-02 в «Разборе», ждёт ответов Q-001, дальше — «Состояния», модель dialog |
| `/razbor PM-02` | Агент razbor показывает пробелы и спрашивает, с чего начать. Не торопит |
| «Должник — с 3 периодов, бизнес подтвердил вчера» | Показывает факт «со слов Разработчик-1, <дата>» и место, спрашивает «Записать?». Вопрос не предлагает |
| «да» | Вызывает `kb fact`, факт в файле |

| `/utro` | Полный отчёт |
| `/vstrecha kb/materials/meetings/2026-10-16-razbor.md` | Субагент возвращает черновик: ответы, предложения (D-001 — «предложено»), ничего не пишет |

**Тесты:** `cd agent && python3 -m unittest discover -s kb/tools/tests -v` — 97 тестов.

**Руками** — в тестовой папке после нескольких коммитов из порций 3–5:
```bash
python3 kb/tools/kb.py report morning --since <хеш первого коммита>
python3 kb/tools/kb.py report morning                 # с даты последнего отчёта или за сутки
python3 kb/tools/kb.py report morning --save          # пишет kb/journal/reports/<сегодня>.md
```

**Что смотреть:** устроит ли аналитика такой отчёт вместо «100+ коммитов». Каждый изменённый файл есть в последнем разделе — это и есть «полный, а не выборка».

## Как проверить порцию 3

**Тесты** — 2 минуты:
```bash
cd agent && python3 -m unittest discover -s kb/tools/tests -v     # 55 тестов, C01–C07 — коммит и права
```

**Руками** — 5 минут, на тестовой базе в отдельной папке:
```bash
R=$(mktemp -d) && cp -R agent/kb/tools/tests/fixture $R/kb && cp -R agent/kb/tools $R/kb/ && cp agent/.gitignore $R/ && cd $R
git init -q && git config user.name "Разработчик-1" && git config user.email dev1@example.local
git add -A && git commit -qm старт && python3 kb/tools/kb.py hooks
python3 kb/tools/kb.py fact PM-02 "Вход" "Выгрузка раз в месяц" "со слов Разработчик-1, 2026-10-18" подтверждено
python3 kb/tools/kb.py commit plan          # смотрите: понятно ли, что войдёт
python3 kb/tools/kb.py commit apply <id>    # id из вывода plan
echo x >> kb/materials/2026-10-01-reglament.md && git commit -am "правка"   # хук должен остановить
```

**В OpenCode** — главное, 10 минут. Скопируйте `agent/opencode.json` в корень тестовой папки и попросите агента:
- «закоммить» — агент вызывает `kb commit plan`, показывает план, после «да» вызывает `apply`, и OpenCode спрашивает разрешение;
- «сделай git commit сам» — OpenCode должен запретить;
- «запушь» — OpenCode должен запретить;
- «поправь kb/tools/kb.py» — OpenCode должен запретить правку.

Права OpenCode в тестах проверяются моей копией правил сопоставления: звёздочка, побеждает последнее совпавшее правило. Так написано в документации 1.18. Как ваша версия разбирает составные команды (`a && b`), покажет только живой прогон.

```bash
python3 kb/tools/kb.py check
python3 kb/tools/kb.py fact PM-02 "Вход" "- Должник с 3 периодов (источник: materials/2026-10-01-reglament.md, стр. 3, confirmed)"
```

Что смотреть:
- `check` на тестовой базе: 0 ошибок, 1 предупреждение — в таблице «Сущности» нарочно нет источника.
- Первая команда `fact` пишет факт и перечисляет, что поправила.
- Вторая и третья отказывают, пишут «НЕ ЗАПИСАНО», файл не меняется.
- Понятен ли текст каждого отказа человеку и слабой модели.

Что в порцию 2 не вошло: S04–S10 (статусы, «достаточно», взятие шага) — порция 5; Q02, Q05, Q07 (`kb ask`, дубли) — порция 4; C01–C07 (коммит) — порция 3.

## Как проверить порцию 1

Время: 30 минут. Запускать нечего.

1. **Структура.** Сравните дерево выше с вашим документом. Отличия — `resheniya.md`, раздел «Отличия от предложенной структуры». Согласны?
2. **`agent/AGENTS.md`.** Это то, что читает модель в каждой сессии. Команд `kb` в нём пока нет — они появятся в порциях 2–6; до этого агент на живой модели запускать бессмысленно. Проверьте:
   - правил 12, и они совпадают с промтом;
   - нет длинных сценариев;
   - текст понятен слабой модели: одна мысль — одно предложение.
3. **Форматы — главное в порции.** `agent/kb/rules/formats.md` и пример шага `agent/kb/tools/tests/fixture/context/process/PM-02-pervoe-uvedomlenie.md`.
   - Шаг читается человеком за 1 минуту: «Коротко» и «Объём».
   - У каждого факта есть проверяемый источник.
   - Пример намеренно неполный: «Состояния» пусты, у поля «лицевой счёт» нет источника. На нём порция 5 покажет `kb step gaps`.
4. **Вопросы.** `agent/kb/tools/tests/fixture/journal/questions/`:
   - Q-001 задан по «задаём» и ждёт бизнес;
   - Q-002 закрыт словами Разработчика-2;
   - Q-003 закрыт пачкой как «вне системы».
5. **Находки не-владельца.** `agent/kb/tools/tests/fixture/context/process/notes/PM-02/qa1.md` — так тестировщик пишет в чужой шаг.
6. **Решение со встречи.** `agent/kb/tools/tests/fixture/journal/decisions/D-001.md` — «предложено», а не «решено».
7. **Флоу и роли.** `agent/kb/rules/flow.md` против карты ролей; `roles/` — по одному файлу на роль. Чего не хватает вашей роли?
8. **Ошибки.** `agent/kb/tools/tests/oshibki.md`: каждый ответ инструмента понятен? Каждую ли ошибку надо ловить?
9. **Ворота.** `agent/kb/rules/gates.md`, раздел «Где правило можно обойти»: что закрываем к понедельнику?
10. **Модели.** `agent/kb/rules/models.md`, таблица «Что вписать».
11. **Покрытие.** `sborka-agenta/pokrytie.md`: ищите строку, которая закрыта словами, а не механизмом.

Если всё устраивает, напишите «да, коммить порцию 1». Отправка в `origin/new-agent` — отдельное «да».
