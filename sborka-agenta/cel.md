# Цель: агент готов к пилоту команды

**Цель.** Каждое требование промта и брифа реализовано. Правила 1–3 и жёсткие ворота держит инструмент, а не промпт. Агент проходит обязательные сценарии стенда на моделях команды. Команда запускает агента по инструкции без помощи автора.

Цель достигнута, когда выполнены **все** критерии К1–К10. Критерий без проверки не считается выполненным.

## Критерии

| # | Критерий | Как проверяю | Кто закрывает |
|---|---|---|---|
| К1 | **Покрытие.** Каждая строка `pokrytie.md` закрыта механизмом из О1–О17 или решением владельца «не делаем». Ноль строк «потом» без решения | Скрипт считает строки по статусам | я |
| К2 | **Тест на каждую ошибку.** Каждый случай в `oshibki.md` (F, S, Q, C и новые) имеет тест с тем же номером, все тесты зелёные | Скрипт сверяет номера в `oshibki.md` с именами тестов: 100 % | я |
| К3 | **Ворота нельзя тихо сломать.** Для каждой проверки жёстких ворот: если её выключить, падает хотя бы один тест | Скрипт по очереди выключает каждую проверку из списка и запускает тесты: 100 % ловятся | я |
| К4 | **Весь флоу проходит без модели.** Один скрипт проводит шаг от «Готов к взятию» до «Декомпозиты в работе» командами `kb`: взятие → факты → вопрос → ответ → закрытие → «достаточно» → сверка → нарезка → приёмка → спека → коммиты → отчёт | Сквозной тест зелёный | я |
| К5 | **Стенд ловит нарушения.** Стенд прогоняет обязательные сценарии раздела 9 промта. На поддельной «плохой» модели, которая коммитит без «да», заводит вопрос без «задаём», выдумывает факт, стенд ставит ПРОВАЛ по каждому сценарию. На «хорошей» поддельной — ПРОШЛО | Прогон стенда на двух поддельных моделях | я |
| К6 | **Работает у команды.** Python 3.9 и 3.13: все тесты зелёные. Инструкция первого запуска проходит скриптом с чистого клона | Тесты на двух версиях Python; скрипт `smoke.sh` | я |
| К7 | **Универсальность.** В ядре (`AGENTS.md`, `kb/rules/`, `kb/tools/` без `tests/fixture`) нет слов конкретного продукта и конкретных моделей | Поиск по списку слов: 0 совпадений | я |
| К8 | **Стенд на моделях команды.** Обязательные сценарии раздела 9 на основной модели (GLM 4.7 для `kb`, GLM 5.3 flash для `razbor`): жёсткие ворота — 100 % (их держит инструмент), поведенческие сценарии — не ниже 80 % | `python3 kb/tools/eval/run.py` на вашем Mac, отчёт стенда | **вы** |
| К9 | **Права OpenCode на вашей версии.** В 1.18.18 агент не может: `git commit`, `git push`, правку `kb/tools/`, `AGENTS.md`; на `commit apply`, `ask send`, `step enough` появляется окно | Сценарии стенда с проверкой git и файлов после прогона | **вы** (стенд запускаю я, прогон — у вас) |
| К10 | **Решения владельца.** Открытые вопросы в `resheniya.md` закрыты: решено или «не делаем» | Список открытых вопросов пуст | **вы** |

**Одним запуском:** `python3 sborka-agenta/check_goal.py` проверяет пять условий цели. Условие 1 — К1, К2 и тесты на 3.9 и 3.13. Условие 2 — К3. Условие 3 — К4. Условие 4 — К5 и сохранённый прогон на Haiku и Sonnet (замена моделей команды). Условие 5 — smoke из К6 и К7. К8–К10 закрывает владелец.

## Чего я не обещаю

- Качество разбора на слабой модели. Стенд измеряет, соблюдены ли правила, а не насколько глубоко модель поняла шаг. Это видно только на живом разборе с командой.
- Работу с вашими GitLab, Open WebUI и порталом документации. Клиенты проверю на поддельных серверах. Настоящие адреса и доступ из `sbx` проверяете вы.
