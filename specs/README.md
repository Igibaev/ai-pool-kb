# Спеки

Спека — источник истины для одного декомпозита. По ней тестировщик пишет сценарии, агент делает тесты и код, архитектор недели проверяет согласованность.

## Где лежат
```
specs/
  _template/
    spec.md       шаблон спеки
    plan.md       шаблон плана задач для агента
  PM-04/
    PM-04-01-<краткое-имя>/
      spec.md
      plan.md
```

## Жизнь спеки
| Статус декомпозита | Что со спекой |
|---|---|
| Опции | Спеки нет, есть строка в нарезке рута |
| Спека | Владелец, тестировщик и веб-разработчик пишут спеку, агент делает красные приёмочные тесты |
| Ревью спеки | Архитектор недели проверяет: модель, согласованность с другими спеками и рутами, допущения |
| Сборка | Спека меняется только через владельца, с отметкой в «Истории изменений» |
| Готово | Изменения модели влиты в `core/`, спека остаётся как описание поведения |

## Что проверяет архитектор недели на ревью
1. «Изменения модели» не противоречат `core/domain-model.md`.
2. Нет дублирования с другими спеками и рутами.
3. Зависимости от других декомпозитов явные.
4. У каждого требования есть сценарий.
5. Допущения записаны, у каждого есть цена ошибки.
6. Необратимые точки помечены.
